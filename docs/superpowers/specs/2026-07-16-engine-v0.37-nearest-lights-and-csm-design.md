# Engine v0.37 — Nearest-N Light Selection + Cascaded Shadow Maps — Design Spec

**Date:** 2026-07-16
**Status:** Approved for planning
**Scope:** Two independent renderer improvements shipped on one branch/PR:
**(A)** nearest-N point-light selection — sort point lights by camera distance so the parallax self-shadow (v0.36) covers the nearest 3, not the first 3 by index; and **(B)** cascaded shadow maps — replace the single fixed directional shadow map with 3 view-frustum cascades for crisp near shadows and covered far shadows. A new `csm_demo` shows the cascades.
**Builds on:** the deferred renderer on `main` (v0.28–v0.36 merged; single directional PCF shadow + point-light parallax self-shadow already present).

## 1. Goal & Motivation

- **(A)** v0.36 packs the parallax self-shadow of the *first 3* point lights (by UBO index) into `gShadow.g/b/a`. If the dominant near light sits at index 4+, it casts no self-shadow. Sorting point lights by distance to the camera before upload makes indices 0/1/2 the nearest 3, so the existing `first-3` shader logic shadows the lights that matter — with no shader change.
- **(B)** The directional shadow is a single 2048² map over a fixed ortho frustum around the origin (`makeLightViewProj(dir, {0,0.5,0}, 16, 0.1, 64)`). It is coarse up close and cannot cover a large scene. Cascaded shadow maps split the camera frustum by depth and give each slice its own tight shadow map, so near geometry gets high resolution and far geometry stays shadowed.

## 2. Decisions (locked)

| Decision | Choice |
| --- | --- |
| (A) Selection metric | Distance from each point light to the **camera position**; ascending sort, on the CPU in `Renderer::endFrame` before the geometry pass |
| (A) Count | Nearest **3** (matches the 3 self-shadow channels `gShadow.g/b/a`); the shader keeps its `first-3` logic unchanged |
| (A) Scope | Only the parallax self-shadow's light selection changes; all point lights still contribute to lighting (order-independent sum) |
| (B) Cascade count | **3** cascades |
| (B) Storage | **3 separate `depthOnly` framebuffers** (reuse the existing single-shadow machinery ×3), sampled via a **branched cascade select** in `shadowPCF` — avoids illegal dynamic `sampler2DShadow[]` indexing and needs no new FBO/array infrastructure |
| (B) Cascade size | 2048² per cascade |
| (B) Split scheme | Practical split: blend of uniform and logarithmic (`λ = 0.5`) between the near plane and a shadow far distance (`≈ 60`) |
| (B) Cascade fit | Per-cascade tight light-space ortho bounding that slice's 8 camera-frustum corners (computed CPU-side in `endFrame` from the camera view/proj) |
| (B) Selection | Per-fragment, by view-space depth vs the 3 split distances; 3×3 PCF within the chosen cascade |
| (B) Light UBO | `LightUniforms` grows to `cascadeViewProj[3]` + `cascadeSplits` (vec4) + `lightDir`; **both** the lighting shader and `mesh.glsl` Light blocks (binding 1) updated in lockstep |
| Demo | New `csm_demo`: long ground + receding pillars under a low sun; `BOTARENA_CSM=1` tints each cascade for visibility |
| Reserved | Texture-array cascades + `sampler2DArrayShadow`; >3 cascades; per-cascade resolution; cascade blend bands; per-fragment nearest-light selection (vs per-camera) |

## 3. Part A — Nearest-N light selection

### 3.1 CPU sort in `Renderer::endFrame`
Today `Renderer::setPointLights` uploads the PointLights UBO immediately. Change it to **store** the light list (`m_pointLights`), and in `endFrame` — before the geometry pass — sort a copy by distance to the camera position (from `m_camera`) ascending, then upload:
```cpp
std::vector<PointLight> sorted = m_pointLights;
const glm::vec3 camPos = glm::vec3(m_camera.cameraPos);
std::stable_sort(sorted.begin(), sorted.end(),
    [&](const PointLight& a, const PointLight& b) {
      return glm::length2(glm::vec3(a.positionRadius) - camPos) <
             glm::length2(glm::vec3(b.positionRadius) - camPos);
    });
m_backend->setPointLights(static_cast<int>(sorted.size()), sorted.data());
```
Indices 0/1/2 are now the nearest 3 → the geometry pass writes their self-shadows to `gShadow.g/b/a`, and the lighting pass attenuates them, exactly as v0.36 — **no shader change**. Emissive billboards use the same (sorted) list, so nothing else shifts.

### 3.2 Why per-camera, not per-fragment
Per-fragment "nearest 3" would require storing 3 light indices per fragment in the g-buffer so the lighting pass could map channels back to lights — too heavy. Nearest-to-camera is the standard approximation: the self-shadows the viewer is closest to are the ones that read.

## 4. Part B — Cascaded Shadow Maps

### 4.1 Cascade setup (CPU, `endFrame`)
Given the camera view/proj and the 3 split distances (`§Decisions`), for each cascade:
1. Take the 8 corners of the sub-frustum between this cascade's near and far split (unproject the NDC cube slice through `inverse(proj*view)`).
2. Build a light view looking along `m_lightDir` at the slice centroid; project the corners into light space; take their AABB → a tight ortho `lightViewProj[i]`.
3. Render the scene depth into `m_shadowFBO[i]` via the existing `executeShadow(entries, lightViewProj[i], …)` (called once per cascade).

Store `cascadeViewProj[0..2]` and the split distances (view-space, positive) in `LightUniforms`; `setLight` uploads the block and remembers the 3 cascade depth textures for the lighting pass to bind.

### 4.2 `LightUniforms` (binding 1)
```cpp
struct LightUniforms {
  glm::mat4 cascadeViewProj[3];
  glm::vec4 cascadeSplits;   // x,y,z = far view-depth of cascades 0,1,2; w unused
  glm::vec4 lightDir;
};
```
Both shader Light blocks change to match this std140 layout:
```glsl
layout(std140, binding = 1) uniform Light {
    mat4 u_cascadeViewProj[3];
    vec4 u_cascadeSplits;
    vec4 u_lightDir;
};
```
`mesh.glsl` still reads only `u_lightDir` (for the directional parallax self-shadow) — but its block must match the new layout so the offset is correct. **This lockstep update is the main risk (see §6).**

### 4.3 `shadowPCF` — cascade select + branched sample
The lighting shader gains 3 cascade depth samplers and picks the cascade from the fragment's view-space depth:
```glsl
uniform sampler2DShadow u_cascade0;
uniform sampler2DShadow u_cascade1;
uniform sampler2DShadow u_cascade2;

int chooseCascade(float viewDepth) {
    if (viewDepth < u_cascadeSplits.x) return 0;
    if (viewDepth < u_cascadeSplits.y) return 1;
    return 2;
}

float sampleCascade(int c, vec3 p) {   // p = light-clip -> [0,1], with bias
    if (c == 0) return texture(u_cascade0, p);
    if (c == 1) return texture(u_cascade1, p);
    return texture(u_cascade2, p);
}
```
`shadowPCF(worldPos, ndl)` computes `viewDepth = -(u_view * vec4(worldPos,1)).z`, chooses the cascade, projects `worldPos` through `u_cascadeViewProj[c]`, and does the existing 3×3 PCF via `sampleCascade`. The branched select (not `sampler[]` indexing) is legal and cheap. The directional term in the lighting pass is unchanged apart from `shadowPCF`'s internals; the parallax directional self-shadow (`gShadow.r`) is independent.

### 4.4 Backend / Renderer wiring
- `m_shadowFBO` becomes `m_shadowFBO[3]` (3 `depthOnly` framebuffers, 2048² each).
- `endFrame` renders 3 shadow passes (one `beginPass`+`executeShadow` per cascade) instead of one.
- `lightingPass` binds the 3 cascade depth textures (extends its shadow-map argument to 3, or takes an array) on 3 texture units and sets `u_cascade0/1/2`.
- `setLight` uploads the expanded `LightUniforms`.

### 4.5 Demo `csm_demo`
`csmdemo::CsmDemoGame` (`csm_demo_game` target): a long ground plane (scaled cube) with a row of pillars receding into the distance under a **low directional sun**, and a camera looking down the row so all three cascades are populated. `BOTARENA_CSM=1` tints fragments by chosen cascade (red/green/blue) to make the splits visible; default off shows the clean shadows. Camera near geometry shows crisp contact shadows; far pillars stay shadowed — the before/after that a single map cannot do.

## 5. Data flow

```
setPointLights(list) -> Renderer stores m_pointLights            (A)
endFrame:
  sort m_pointLights by camera distance -> upload UBO            (A: nearest 3 -> indices 0/1/2)
  for c in 0..2:                                                 (B)
     fit lightViewProj[c] to camera sub-frustum[c]
     beginPass(m_shadowFBO[c]); executeShadow(entries, lightViewProj[c])
  setLight(cascadeViewProj[0..2], splits, dir; bind 3 depth maps)
  geometry pass -> g-buffer + gShadow (self-shadow, nearest 3 points)
  lighting pass:
     shadowPCF: choose cascade by view depth -> PCF that cascade  (B)
     directional *= (1 - cascadedShadow) * gShadow.r
     point light i *= (i<3 ? gShadow[i+1] : 1)                    (A benefits: i=0..2 are nearest)
```

## 6. Risks & mitigations

- **(B) Light UBO layout skew** between C++ `LightUniforms`, the lighting shader, and `mesh.glsl`. The single biggest risk. Mitigation: all three change in one task; `mesh.glsl` only reads `u_lightDir` but its block must match the full std140 layout; verified by the existing games still rendering directional shadows *and* `normalmap_demo`'s parallax directional self-shadow (which reads `u_lightDir`).
- **(B) CSM changes every game's directional shadow** — this is a quality upgrade, not an additive change, so arena/shooter shadows are *not* pixel-identical (they get crisper near). Mitigation: regression is "directional shadows still present and correct, improved near crispness," verified by screenshot; documented as an intentional visible change.
- **(B) Cascade seams / peter-panning.** Mitigation: per-cascade slope-scaled bias (reuse the existing `shadowPCF` bias); tight per-cascade fit; the `BOTARENA_CSM` tint makes seams debuggable. Cascade blend bands are reserved.
- **(A) Sort cost.** Point lights ≤32; a per-frame `stable_sort` of ≤32 elements is negligible.
- **(A) Billboard/order coupling.** Emissive billboards read the same sorted list, so light order stays consistent across passes; nothing depends on the original order.
- **(B) Extra texture units.** Lighting pass uses units 0–9; the 3 cascade maps replace the single shadow map on unit 3 and add units 10–11. Well within the ≥16 guaranteed combined units.

## 7. Testing

- **(A)** A deterministic scene with **>3 point lights** at different distances (e.g. an extended `parallax_light_demo` preset, or a check in `csm_demo`): the 3 lights whose self-shadows appear are the 3 nearest the camera; moving the camera changes which 3 shadow. `parallax_light_demo` (3 lights) is unchanged (nearest 3 == all 3).
- **(B)** `csm_demo` screenshots: near pillars cast crisp contact shadows, far pillars stay shadowed; `BOTARENA_CSM=1` shows 3 distinct cascade regions tiling the ground by distance. Regression: arena/shooter still show correct directional shadows (crisper near); `normalmap_demo` parallax directional self-shadow still reads (`u_lightDir` intact after the UBO change). Full build + suite green.

## 8. Open items (deferred, not blocking)

- Texture-array cascades with `sampler2DArrayShadow` (one sampler, no branch).
- More than 3 cascades; per-cascade resolution (smaller far maps).
- Cascade blend bands to hide seams.
- Per-fragment nearest-light selection (vs per-camera) for the parallax self-shadow.

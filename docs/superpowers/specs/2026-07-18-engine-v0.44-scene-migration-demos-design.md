# Engine v0.44 — Migrate the rendering-technique demos onto Scene

## Problem

Six games still render outside the `Scene`/ECS system (manual `Camera`,
`MeshRenderer::submit`, `setPointLights`/`setLightDirection`). Because
`LightComponent`/`MeshComponent`/`ModelComponent` are all collected by
`Scene::render`, none of these six can be scene-driven until they are migrated
onto `Scene`. This slice migrates the three that migrate *cleanly* — the
rendering-technique demos csm_demo, normalmap_demo, and parallax_light_demo —
each of which draws standard geometry lit by standard lights, with only a thin
text overlay (which was never `Scene`'s responsibility).

The other three (particles, camera_demo, billboard_demo) are deferred: their
core content (a custom `ParticleSystem`/`submitParticles` pipeline, runtime
switching between four camera types + an SDF HUD, and a bespoke
damage-number billboard simulation) has no `Scene` component and would remain
manual even after "migration."

Two of the three in scope introduce a genuinely new pattern — an **animated
`LightComponent`**, whose `TransformComponent` is updated per frame.

## Background: how Scene builds the camera

`Scene::cameraUniforms(aspect)` finds the primary `CameraComponent` entity and
returns `makeCameraUniforms(viewMatrix(tf), projectionMatrix(cam, aspect))`,
where (`engine/scene/SceneCamera.hpp`):

```cpp
glm::mat4 viewMatrix(const TransformComponent& t) {
  const glm::mat4 world = glm::translate(glm::mat4(1.0f), t.translation) *
                          glm::mat4_cast(t.rotation);
  return glm::inverse(world);
}
glm::mat4 projectionMatrix(const CameraComponent& c, float aspect) {
  // perspective: glm::perspective(radians(c.fov), aspect, c.perspNear, c.perspFar)
}
```

The three games each use a raw `PerspectiveCamera` with a fixed
`lookAt(eye, target)` and `setPerspective(55, aspect, 0.1, 100)`.
`PerspectiveCamera::view()` is `glm::lookAt(m_position, m_position + forward(),
{0,1,0})`, and its `forward()` — reconstructed from the yaw/pitch that
`lookAt` derives via `asin`/`atan2` — equals `normalize(target - m_position)`
exactly. So the camera's view is **exactly** `glm::lookAt(eye, target,
{0,1,0})`, and its projection is exactly `glm::perspective(radians(55), aspect,
0.1, 100)` = `projectionMatrix(CameraComponent{fov=55,near=0.1,far=100},
aspect)`. Reproducing the camera on `Scene` is therefore faithful — but not
bit-exact: `viewMatrix` rebuilds the view from a `glm::quat` (`quat_cast →
mat4_cast`), perturbing it by ~1e-6 vs the old direct `glm::lookAt`. On
non-shadowed content that is sub-pixel and invisible; on these shadow-heavy
scenes (CSM / PCF / parallax self-shadow) it amplifies into a scattering of
sub-visual shadow-acne dither. So the screenshot gate is NOT a literal AE = 0
— it is: every migrated value byte-identical to the deleted code, the diff
collapsing to a handful of pixels under `compare -fuzz 2-5%` (PSNR > 60 dB),
and a heatmap with clean silhouette edges / unshifted light hotspots (a real
camera or geometry bug red-outlines silhouettes and does not collapse).

## Design

### 1. `lookAtTransform` — a reusable camera-conversion helper

A raw `lookAt(eye, target)` camera becomes a `CameraComponent` entity by giving
its `TransformComponent` a translation + rotation whose `viewMatrix` equals
`glm::lookAt(eye, target, up)`. Add an inline, GL-free helper to
`engine/scene/SceneCamera.hpp` (beside `viewMatrix`):

```cpp
// A TransformComponent whose viewMatrix() equals glm::lookAt(eye, target, up).
// world = inverse(lookAt) = translate(eye) * rotate; extract eye + rotation.
inline TransformComponent lookAtTransform(const glm::vec3& eye,
                                          const glm::vec3& target,
                                          const glm::vec3& up = glm::vec3(0.0f, 1.0f, 0.0f)) {
  const glm::mat4 world = glm::inverse(glm::lookAt(eye, target, up));
  TransformComponent t;
  t.translation = eye;
  t.rotation = glm::quat_cast(glm::mat3(world));
  return t;
}
```

- `glm::lookAt` and `glm::quat_cast` are in `glm/gtc/matrix_transform.hpp` and
  `glm/gtc/quaternion.hpp` respectively — **`gtc`, allowed**; `glm::inverse`
  is core. No `gtx`.
- Because the rotation part of `inverse(lookAt)` is orthonormal, the
  `quat_cast → mat4_cast` round-trip reproduces it to ~1e-6, i.e. sub-pixel.
- Unit-tested (GL-free): for several representative `(eye, target)` pairs,
  `viewMatrix(lookAtTransform(eye, target))` ≈ `glm::lookAt(eye, target,
  {0,1,0})` component-wise within a small epsilon.

### 2. Animated `LightComponent` pattern

`LightComponent` is data on an entity; `collectLights` reads the entity's live
`TransformComponent` every frame. An animated light is therefore just an entity
whose `TransformComponent.translation` is mutated per frame **before**
`m_scene.render(...)`:

- **Directional** (normalmap_demo): `directionalDir = normalize(translation)`,
  so set `translation` to the (un-normalized) direction vector the old code
  passed to `setLightDirection`.
- **Point** (parallax_light_demo): set `translation` to the orbit position the
  old code packed into `PointLight.positionRadius.xyz`.

The game stores the animated light `SceneObject`(s) as members and updates their
`translation` in `onRender`, reusing the existing `m_time`/`BOTARENA_SCREENSHOT`
freeze logic verbatim so screenshots stay deterministic. No new component or
system is introduced (YAGNI) — a game that animates a light mutates its
transform, exactly as a game that moves an object would.

### 3. Per-game migration

Each game gains an `engine::Scene m_scene;` member. `onAttach` creates the
camera entity (via `lookAtTransform`) + the light entities + the geometry
entities (transform-only); `ensureResources` attaches `MeshComponent`s once
materials exist (materials need a live `Renderer`, so this stays lazy, matching
scene_demo/models). `onRender` drops the manual `setCamera` /
`setLightDirection` / `setPointLights` / `MeshRenderer` submit loop and calls
`m_scene.render(renderer, aspect)`; the SDF text stays as a `renderer.drawText`
overlay afterward. The raw `PerspectiveCamera m_camera` member is removed.

**csm_demo** (static, LOW):
- Camera: `lookAtTransform({5,7.5,9}, {-1,0,-13})`, `CameraComponent{fov=55,
  perspNear=0.1, perspFar=100, primary=true}`.
- Geometry: ground (`translate {0,-0.1,-18}`, `scale {30,0.2,60}`, `m_groundMat`)
  + 8 pillars (`translate {0,1.4,-2-5i}`, `scale {0.8,2.8,0.8}`, `m_pillarMat`).
- Light: one static directional entity, `translation {0.62,0.5,0.12}`.
- Text caption unchanged.

**normalmap_demo** (animated directional, MED):
- Camera: `lookAtTransform({2.6,2,10}, {0,1.6,0})`, same `CameraComponent`.
- Geometry: three walls (`translate {x,1.5,0}`, `scale {2,3,0.2}`) with
  `m_flatMat`/`m_mappedMat`/`m_parallaxMat` at x = −4.4/0/+4.4.
- Lights: one **animated directional** entity (member) whose `translation` is
  set each frame to `{cos(a), 0.28, sin(a)*0.35+0.32}` with
  `a = m_screenshot ? (m_lightPreset==1 ? 2.3 : 0.7) : m_time*0.5` (unchanged
  freeze logic); one static point fill entity `translation {0,2,6}`,
  `color {0.5,0.55,0.65}`, `intensity 0.8`, `radius 24`.
- Billboard labels unchanged.

**parallax_light_demo** (3 animated points, MED):
- Camera: `lookAtTransform({0.5,5.5,7}, {0,0,-0.5})`, same `CameraComponent`.
- Geometry: one floor (`translate {0,-0.15,0}`, `scale {6,0.3,6}`, `m_floorMat`).
- Lights: three **animated point** entities (members) with static
  `color = lightColors[i]`, `intensity 4.5`, `radius 12`, whose `translation`
  is set each frame to `{cos(ai)*2.4, 0.9, sin(ai)*2.4}` where
  `ai = a + 2π·i/3` and `a = m_screenshot ? (preset 2→3.9, 1→2.2, else 0.4)
  : m_time*0.7` (unchanged freeze logic); one static directional entity
  `translation {0.9,0.12,0.25}`.
- Screen-space caption unchanged.

### 4. Wiring stays additive

`Scene::render` is untouched — both setters remain guarded. The
additive→authoritative flip is still deferred (three off-Scene games remain).

## Testing

- `tests/test_scene_camera.cpp` (new, GL-free, Catch2): `lookAtTransform` +
  `viewMatrix` reproduce `glm::lookAt` for several `(eye,target)` pairs within
  epsilon; also assert the translation equals `eye`.
- Each of the three games screenshot-verified with
  `BOTARENA_SCREENSHOT=<path> ./build/<game>` against its pre-migration
  baseline. The gate is not literal AE = 0 (see the camera section): raw AE is
  a small sub-visual dither on these shadow-heavy scenes, verified by the diff
  collapsing under `compare -fuzz 2-5%` (PSNR > 60 dB) with clean silhouettes.
- Full `bot_arena_tests` suite stays green; `SceneRender.cpp`/`SceneCamera.hpp`
  remain GL-free so the tests target is unaffected.

## Non-goals / reserved

- **particles, camera_demo, billboard_demo** — deferred; their core content is
  not `Scene`-expressible (a follow-up would need particle/billboard/multi-camera
  support or accept partial migrations with a manual tail).
- **The additive→authoritative flip** — still deferred until every game is on
  `Scene`.
- **A dedicated light-animation component/system** — not introduced; per-frame
  transform mutation suffices for these two demos.
- **Multiple directional lights**, **per-submesh material overrides**,
  **sort/cull/instancing**, **`addComponent<T>` empty-tag fix** — reserved.

## Decisions table

| Decision | Choice | Why |
|---|---|---|
| Scope | csm_demo + normalmap_demo + parallax_light_demo | the 3 that migrate cleanly; the other 3 have non-Scene-able core content |
| Camera conversion | `lookAtTransform` helper in `SceneCamera.hpp`, unit-tested | `PerspectiveCamera::view() == glm::lookAt(eye,target,{0,1,0})` exactly → AE=0; reusable |
| Animated lights | per-frame `TransformComponent.translation` mutation in `onRender` | `collectLights` reads live transforms; no new component/system (YAGNI) |
| Mesh attach | lazy in `ensureResources` | materials need a live `Renderer`, as in scene_demo/models |
| Text | stays a `renderer.drawText` overlay | text was never a `Scene` component |
| Wiring | stays additive | flip precondition (all games on `Scene`) still unmet |
| Verification | `lookAtTransform` unit test + per-game screenshot AE=0 | mirrors prior slices' proof method |

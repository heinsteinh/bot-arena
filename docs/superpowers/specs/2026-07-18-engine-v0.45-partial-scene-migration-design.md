# Engine v0.45 — Partial-migrate the last 3 games onto Scene

## Problem

After v0.44, eight games are scene-driven and three remain off `Scene`:
particles, camera_demo, billboard_demo. Each has *core content* `Scene` has no
component for — a custom `ParticleSystem`/`submitParticles` pipeline, runtime
switching between four camera types + an SDF HUD, and a bespoke damage-number
billboard simulation. This slice **partially** migrates all three: their camera,
geometry, and lights move onto `Scene` (`CameraComponent` + `MeshComponent` +
`LightComponent`, drawn by `m_scene.render`), while their bespoke content stays
a manual tail after the render call. This removes the per-game
`MeshRenderer`/`setPointLights` boilerplate and — since none of the three will
set lights manually afterward — leaves every game that calls `Scene::render`
fully light-driven, the precondition for a future additive→authoritative flip.

## Design

### Camera: game-owned, driving the Scene camera

A partial migration keeps each game's bespoke camera logic; the camera just
drives the single primary `CameraComponent` entity instead of
`renderer.setCamera` directly.

**billboard_demo, particles** use a *static* `OrbitCameraController` (fov 60,
near 0.1, far 100), whose `update` computes
`m_camera.lookAt(target + offset*distance, target)` with
`offset = {cos(pitch)cos(yaw), sin(pitch), cos(pitch)sin(yaw)}`. Since the orbit
never moves, we compute `eye = target + offset*distance` once in `onAttach` and
build the camera entity with the existing `lookAtTransform(eye, target)` helper
(v0.44) + a static `CameraComponent{fov=60, perspNear=0.1, perspFar=100,
primary=true}`. This **retires their `OrbitCameraController`** entirely.

**camera_demo** switches among four cameras per frame (orbit auto-rotating via
`m_time`, fly reading input, ortho top-down, fixed-front). Its cameras stay; a
new helper syncs the *active* camera's view into the Scene camera each frame.

#### New helper: `cameraTransformFromView`

`lookAtTransform` builds a `TransformComponent` from an `(eye, target)` pair; the
general form builds one from any camera's *view matrix* (needed for fly/ortho,
which aren't a clean eye/target lookAt). Add to `engine/scene/SceneCamera.hpp`
(inline, GL-free, beside `lookAtTransform`):

```cpp
// A TransformComponent whose viewMatrix() equals the given view matrix.
// world = inverse(view) = translate * rotate; extract translation + rotation.
inline TransformComponent cameraTransformFromView(const glm::mat4& view) {
  const glm::mat4 world = glm::inverse(view);
  TransformComponent t;
  t.translation = glm::vec3(world[3]);
  t.rotation = glm::quat_cast(glm::mat3(world));
  return t;
}
```

`glm::inverse`/`glm::mat3`/`glm::vec3` are core; `glm::quat_cast` is `gtc` (both
already included by `SceneCamera.hpp`). Unit-tested: `viewMatrix(
cameraTransformFromView(V)) ≈ V` for a perspective lookAt view and an
orthographic-style lookAt view (a rigid view matrix round-trips exactly up to
the quat's ~1e-6).

For camera_demo, each frame: compute the active camera via the existing
`activeCamera(aspect)` (unchanged), then set the primary camera entity's
`TransformComponent = cameraTransformFromView(cam.view())` and its
`CameraComponent` projection to match the active view type — perspective
(`fov=60` orbit/fly, `fov=55` front; near 0.1, far 100) or **orthographic**
top-down (`orthoSize=24`, `orthoNear=-100`, `orthoFar=100`, reproducing the old
`setBounds(-12·aspect, 12·aspect, -12, 12, -100, 100)`). Then `m_scene.render`.

### Per-game migration

Each game gains `engine::Scene m_scene;`. Geometry becomes `MeshComponent`
entities (materials attached lazily once a `Renderer` exists), lights become
`LightComponent` entities, `onRender` calls `m_scene.render(renderer, aspect)`,
and the bespoke content follows as a manual tail. The manual
`setCamera`/`setPointLights`/`MeshRenderer` submit loop and now-dead
`MeshRenderer.hpp`/`PointLight.hpp` includes are removed.

**billboard_demo** (static camera):
- Camera: `eye = {0,0.5,0} + offset(yaw,pitch)*15` (yaw/pitch resolved from the
  `BOTARENA_ORBIT` env preset as today, default 35/22), `lookAtTransform(eye,
  {0,0.5,0})`, `CameraComponent{fov=60,...}`.
- Geometry: ground (`translate {0,-0.05,0}`, `scale {24,0.1,24}`, `m_groundMat`)
  + 6 static enemy cubes (`translate m_enemies[i]`, `scale {1,1.2,1}`,
  `m_enemyMat`).
- Light: one point, `translate {3,6,3}`, `color {1,0.95,0.9}`, intensity 3,
  radius 20.
- Manual tail (unchanged): damage-number `cameraBillboard` text + the screen HUD.

**particles** (static camera, animated bouncers):
- Camera: `eye = {0,1,0} + offset(40,25)*14`, `lookAtTransform(eye, {0,1,0})`,
  `CameraComponent{fov=60,...}`.
- Geometry: ground (`translate {0,-0.05,0}`, `scale {20,0.05,20}`, `m_groundMat`)
  + 6 bouncer cubes (`scale 0.3`, `m_bouncerMat`). Bouncers **move** (physics in
  `stepSim`), so their entity `TransformComponent.translation` is synced from
  `m_bouncers[i].position` each frame in `onRender` before `m_scene.render`
  (same live-transform pattern as v0.44's animated lights).
- Light: one point, `translate {0,6,0}`, `color {1,1,1}`, intensity 2, radius 20.
- Manual tail (unchanged): `submitParticles` after `m_scene.render`; the ImGui
  editor.

**camera_demo** (per-frame camera sync):
- Camera: per-frame sync (above). `activeCamera(aspect)` + the 4 camera members
  + `m_view`/`m_time`/Space-switch logic stay.
- Geometry: ground (`translate {0,-0.05,0}`, `scale {24,0.1,24}`, `m_groundMat`)
  + 8 ring cubes (`translate {cos·5, 0.75, sin·5}`, `rotation = angleAxis(a, +Y)`,
  `scale {1.2,1.5,1.2}`, `m_cubeMats[i%4]`) + center pillar (`translate {0,1,0}`,
  `scale {1.5,2,1.5}`, `m_cubeMats[3]`).
- Lights: 4 static point lights (`{±5, 3, ±5}`, `palette[i]`, intensity 3,
  radius 12) — same as the old loop.
- Manual tail (unchanged): the SDF HUD, including the `eye` readout computed from
  the active manual camera's `view()`.

### Wiring stays additive

`Scene::render` is untouched. After this slice every game calls `Scene::render`
and none sets lights manually — the authoritative flip becomes possible in a
later slice, but is not done here.

## Testing

- `tests/test_scene_camera.cpp` gains `cameraTransformFromView` cases (GL-free,
  Catch2): `viewMatrix(cameraTransformFromView(V)) ≈ V` for a perspective and an
  ortho-style view.
- Each game screenshot-verified against its pre-migration baseline. These scenes
  use plain-material cubes + point lights (less shadow area than v0.44), so raw
  AE should be small; the gate is the v0.44 **shadow-aware** one — every migrated
  value byte-identical to the deleted code, the diff **collapsing under
  `compare -fuzz 2-5%`** (PSNR > 60 dB), and a heatmap with clean silhouettes
  (particles/camera_demo screenshots are deterministic: particles warms up a
  fixed sim in `onAttach`, billboard/camera_demo freeze under
  `BOTARENA_SCREENSHOT`).
- `SceneCamera.hpp` stays GL-free; full `bot_arena_tests` suite stays green.

## Non-goals / reserved

- **Native `Scene` support for particles / billboards / multi-camera switching**
  — not built; those stay manual tails. This is a *partial* migration by design.
- **The additive→authoritative flip** — now unblocked (every game is on Scene +
  light-driven) but deferred to its own slice.
- **Retiring `FlyCameraController`/`OrthographicCamera`** — camera_demo still
  uses them (synced into the Scene camera); a full ECS multi-camera model is out
  of scope.
- **Per-submesh material overrides, sort/cull/instancing, `addComponent<T>`
  empty-tag fix** — reserved.

## Decisions table

| Decision | Choice | Why |
|---|---|---|
| Scope | all 3 games, partial | user-chosen; core content not Scene-expressible, stays a manual tail |
| Static-orbit cameras | compute eye + `lookAtTransform`, retire `OrbitCameraController` | orbit never moves; reuses v0.44 helper; removes a standalone controller |
| camera_demo camera | per-frame sync via `cameraTransformFromView` + per-view `CameraComponent` projection | keeps the bespoke 4-camera switch; handles perspective↔ortho |
| Animated bouncers | per-frame `TransformComponent.translation` sync | same live-transform pattern as v0.44 animated lights |
| Ring-cube rotation | `TransformComponent.rotation = angleAxis(a, +Y)` | `angleAxis` is `gtc`; localTransform reproduces the old `translate·rotate·scale` |
| Screenshot gate | v0.44 shadow-aware fuzz-collapse + heatmap | camera quat round-trip → possible sub-visual dither |
| Wiring | stays additive | flip deferred to its own slice |

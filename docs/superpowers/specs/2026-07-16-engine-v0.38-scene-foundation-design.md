# Engine v0.38 — Scene + SceneObject (EnTT) Foundation — Design Spec

**Date:** 2026-07-16
**Status:** Approved for planning
**Scope:** Introduce a `Scene` that owns one `entt::registry`, a lightweight `SceneObject` handle facade over `entt::entity`, the first data-oriented components (`IDComponent`, `TagComponent`, `TransformComponent`, `CameraComponent`), and a single **primary camera** whose `CameraUniforms` the renderer consumes. A new `scene_demo` proves the path. No camera controllers, no `MeshComponent`, no migration of existing games this slice.
**Builds on:** the deferred renderer on `main` (v0.28–v0.37). EnTT is already a dependency and is already used ad hoc by `arena`/`shooter`.

## 1. Goal & Motivation

Every game currently manages its own camera object and (sometimes) its own `entt::registry`, and the standalone camera classes each store their **own** position/orientation — a second source of truth once transforms exist. This slice establishes one scene-graph model: a single registry per `Scene`, a `SceneObject` façade for ergonomic component access, and a clean split where **`TransformComponent` is the single source of truth for where a camera is** and **`CameraComponent` says only how it projects**. The renderer keeps consuming exactly what it consumes today — a `CameraUniforms` — so integration is additive.

## 2. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Entity storage | **One `entt::registry`, owned by `Scene`.** No parallel `std::vector<Component*>` ownership tree |
| `SceneObject` | Non-owning, copyable handle `{entt::entity, Scene*}`; `operator bool` = `registry.valid(entity)` |
| Components | **Data-oriented, stored only in EnTT.** No `shared_ptr<Camera>` — go straight to the data-oriented `CameraComponent` |
| Transform source of truth | `TransformComponent` holds translation + euler rotation + scale; the camera's **view** derives from it (`inverse(T·R)`), never stored twice |
| Camera projection | `CameraComponent` holds projection params only (`ProjectionType` + perspective/ortho fields + `aspect`/`primary`/`fixedAspectRatio`) |
| Renderer integration | Add `Renderer::setCamera(const CameraUniforms&)` overload; `Scene::cameraUniforms(aspect)` composes view×projection. The existing `setCamera(const Camera&)` stays |
| Existing cameras | `PerspectiveCamera`/`OrthographicCamera`/`Camera2D` **untouched** (legacy path); consolidation deferred |
| Transform math | `glm::quat` + `glm::mat4_cast` from **`<glm/gtc/quaternion.hpp>`** (non-experimental) |
| Demo | New `scene_demo`: a Scene owns a primary camera + a few visual objects; meshes submitted via `MeshRenderer` using each object's `TransformComponent` |
| Out of scope | Camera controllers / the 4 behaviours; `MeshComponent` + `Scene::render` of geometry; parent/child hierarchy; migrating `arena`/`shooter` |

## 3. Components & changes

### 3.1 File layout (new `engine/scene/`)
- `SceneObject.hpp` — templated handle façade (header-only).
- `Scene.hpp` / `Scene.cpp` — owns the registry; object lifecycle; primary-camera query; `cameraUniforms`.
- `Components.hpp` — `ProjectionType`, `IDComponent`, `TagComponent`, `TransformComponent`, `CameraComponent`.
- `SceneCamera.hpp` — free functions `projectionMatrix(const CameraComponent&, float aspect)` and `viewMatrix(const TransformComponent&)`.

### 3.2 `SceneObject` (façade)
```cpp
class SceneObject {
 public:
  SceneObject() = default;
  SceneObject(entt::entity handle, Scene* scene);

  template <class T, class... A> T& addComponent(A&&... args);   // asserts !has
  template <class T> T& getComponent();                          // asserts has
  template <class T> const T& getComponent() const;
  template <class T> bool hasComponent() const;
  template <class T> void removeComponent();                     // asserts has

  explicit operator bool() const;        // scene && registry.valid(handle)
  operator entt::entity() const { return m_handle; }
  bool operator==(const SceneObject&) const;

 private:
  entt::entity m_handle{entt::null};
  Scene* m_scene{nullptr};
};
```
The façade forwards to `m_scene->registry()`. It stores no component data itself.

### 3.3 `Scene`
```cpp
class Scene {
 public:
  SceneObject createObject(std::string_view name = {});  // adds ID + Tag + Transform
  void destroyObject(SceneObject object);

  SceneObject primaryCamera();          // first entity with CameraComponent.primary; else invalid
  CameraUniforms cameraUniforms(float aspect) const;  // view(Transform) × projection(CameraComponent)

  entt::registry& registry() { return m_registry; }
  const entt::registry& registry() const { return m_registry; }

 private:
  entt::registry m_registry;
  uint64_t m_nextId = 1;                // deterministic IDs (testable)
  friend class SceneObject;
};
```
- `createObject` creates an entity and attaches `IDComponent{m_nextId++}`, `TagComponent{name or "SceneObject"}`, `TransformComponent{}`.
- `destroyObject` calls `registry.destroy(entity)` (guarded by validity).
- `primaryCamera` iterates the `CameraComponent` view and returns the first with `primary == true` (else a default/invalid `SceneObject`).
- `cameraUniforms(aspect)`: if no primary camera → identity `CameraUniforms`; else `view = viewMatrix(primary.TransformComponent)`, `projection = projectionMatrix(primary.CameraComponent, aspect)`, returned through `makeCameraUniforms(view, projection)` (so `cameraPosition`/`viewProjection`/`invViewProjection` are consistent).

### 3.4 Components (`Components.hpp`)
```cpp
enum class ProjectionType { Perspective, Orthographic };

struct IDComponent  { uint64_t id = 0; };
struct TagComponent { std::string name; };

struct TransformComponent {
  glm::vec3 translation{0.0f};
  glm::vec3 rotation{0.0f};   // euler radians (pitch=x, yaw=y, roll=z)
  glm::vec3 scale{1.0f};
  glm::mat4 localTransform() const;   // translate(T) * mat4_cast(quat(rotation)) * scale(S)
};

struct CameraComponent {
  ProjectionType type = ProjectionType::Perspective;
  float fov = 45.0f;             // vertical FOV degrees (perspective)
  float perspNear = 0.1f, perspFar = 1000.0f;
  float orthoSize = 10.0f;       // vertical extent (orthographic)
  float orthoNear = -1.0f, orthoFar = 1.0f;
  float aspect = 16.0f / 9.0f;   // used when fixedAspectRatio
  bool primary = true;
  bool fixedAspectRatio = false;
};
```

### 3.5 Camera math (`SceneCamera.hpp`)
- `viewMatrix(const TransformComponent& t)` = `inverse(translate(t.translation) * mat4_cast(quat(t.rotation)))` — scale intentionally excluded from the view.
- `projectionMatrix(const CameraComponent& c, float aspect)`:
  - effective aspect = `c.fixedAspectRatio ? c.aspect : aspect`.
  - **Perspective:** `glm::perspective(radians(c.fov), effAspect, c.perspNear, c.perspFar)`.
  - **Orthographic:** half-height `h = c.orthoSize * 0.5`, half-width `w = h * effAspect`; `glm::ortho(-w, w, -h, h, c.orthoNear, c.orthoFar)`.

### 3.6 Renderer integration
Add one overload alongside the existing one:
```cpp
void setCamera(const CameraUniforms& uniforms) { m_camera = uniforms; }
```
A game's `onRender` calls `renderer.setCamera(scene.cameraUniforms(aspect))`. Nothing else in the renderer changes; mesh submission stays in the game via `MeshRenderer`.

## 4. Data flow (this slice)

```
Scene (owns entt::registry)
  createObject() -> entity + IDComponent + TagComponent + TransformComponent
  camera object  += CameraComponent{primary}
game onRender:
  scene.cameraUniforms(aspect):
     primary = first CameraComponent.primary
     view  = inverse(translate·rotate) of primary.TransformComponent
     proj  = perspective/ortho from primary.CameraComponent
     -> makeCameraUniforms(view, proj)
  renderer.setCamera(uniforms)              // NEW overload
  for each visual SceneObject:              // demo iterates its own objects
     meshRenderer.submit(mesh, mat, obj.TransformComponent.localTransform())
  renderer draws (unchanged deferred path)
```

## 5. Demo — `scene_demo`

`scenedemo::SceneDemoGame` (`scene_demo_game` target):
- Owns a `Scene`.
- Creates a **camera** `SceneObject` (`TransformComponent` positioned above/behind the origin with a downward pitch; `CameraComponent{ primary = true, perspective }`).
- Creates a few **visual** `SceneObject`s (ground + a small arrangement of cubes) with distinct `TransformComponent`s.
- `onRender`: `renderer.setCamera(scene.cameraUniforms(aspect))`, then submits each visual object's cube mesh via `MeshRenderer` using `obj.getComponent<TransformComponent>().localTransform()`.
- Proves: the scene owns the primary camera (renderer pulls its uniforms) and the objects' transforms drive rendering (single source of truth). An SDF HUD label names the demo.
- The camera uses a pitch-only tilt (looking down −Z); a general look-at→euler helper is deferred (keeps the slice off the experimental GLM headers).

## 6. Testing

Unlike the GL renderer, the scene/component layer is **pure CPU + header-only EnTT**, so this slice ships **real unit tests** (`tests/test_scene.cpp`, Catch2):
- **SceneObject façade:** `addComponent` returns a ref and `hasComponent` becomes true; `getComponent` returns the same instance; `removeComponent` clears it; `operator bool` is false for a default handle and after `destroyObject`; `operator entt::entity` round-trips.
- **Scene lifecycle:** `createObject` auto-adds `IDComponent`+`TagComponent`+`TransformComponent`; IDs are unique and monotonically increasing; `TagComponent.name` respects the argument (and defaults otherwise); `destroyObject` invalidates the handle.
- **Primary camera:** `primaryCamera` returns invalid with no cameras; returns the sole primary; returns the first when several are `primary`.
- **Transform math:** `localTransform()` equals a hand-built `translate·rotate·scale`; `viewMatrix` equals `inverse(translate·rotate)` and its inverse's translation column equals `translation` (camera position).
- **Projection math:** perspective params equal `glm::perspective`; ortho params equal the expected `glm::ortho`; `fixedAspectRatio` uses the component aspect, otherwise the passed aspect.
- **cameraUniforms:** composition matches `makeCameraUniforms(viewMatrix, projectionMatrix)` and `cameraPosition == translation`.

The `scene_demo` is additionally screenshot-verified (objects visible through the scene-owned camera). Full build + suite stay green.

## 7. Risks & mitigations

- **Two entity systems.** Mitigation: the whole point — one `entt::registry` in `Scene`, `SceneObject` is only a handle; no second ownership model. Existing games keep their own ad-hoc registries until a later migration slice (documented).
- **Two sources of truth for camera pose.** Mitigation: `CameraComponent` carries **no** position/orientation; view derives from `TransformComponent`. The data-oriented decision (no `shared_ptr<Camera>`) is what makes this hold from day one.
- **Euler/quaternion convention.** Mitigation: `TransformComponent` uses `glm::quat(euler)` + `mat4_cast` consistently for both `localTransform` and `viewMatrix`; the demo camera uses a pitch-only tilt (unambiguous); a general look-at helper is deferred. Tests pin the math to hand-built matrices.
- **Dangling `SceneObject` after destroy.** Mitigation: `operator bool` validates against the registry every use; the façade asserts on `getComponent`/`removeComponent` of a missing component.
- **Renderer coupling.** Mitigation: additive `CameraUniforms` overload only; the renderer never learns about `Scene`.

## 8. Open items (deferred, not blocking)

- Camera **controller** components + systems (Fly / Orbit / Follow / 2D) — the four behaviours.
- `MeshComponent` + `Scene::render` (scene-driven geometry submission).
- Parent/child transforms (world vs local), scene traversal/lifecycle callbacks.
- Migrating `arena`/`shooter` onto `Scene`; deciding whether to retire the standalone camera classes or keep them as thin helpers.
- A general `lookAt`→transform helper (and revisiting rotation representation: euler vs quat storage).

# Engine v0.28+ — Text System Architecture — Design Spec

**Date:** 2026-07-15
**Status:** Approved for planning
**Scope:** Replace the single bitmap-atlas text path with a modular, backend-agnostic
text-rendering system: a central `FontManager`, a backend-tagged `FontAsset`, a
codepoint-keyed `GlyphAtlas`, surface-agnostic `TextLayout`, a shared `TextStyle`, and a
batching `TextRenderer` with a per-backend shader/pipeline seam. Designed for Bitmap / SDF /
MSDF backends, offline and runtime atlas generation, rich text, effects (outline, cartoon
stroke, glow, shadow, gradient), and future world-space 3D text — implemented in slices.
**Builds on:** v0.17 FreeType bitmap text, on `main`.
**Inspiration:** rougier/freetype-gl (texture-atlas, texture-font, markup), Dear ImGui text
batching, professional engine text stacks.

## 1. Goal & Motivation

The current implementation (`engine/renderer/text/Font.cpp`) bakes ASCII glyphs 32–126 into
one R8 bitmap atlas, stores metrics in a fixed `std::array<Glyph,128>`, and renders
screen-space quads whose fragment shader is `alpha = atlas.r; color = uColor`. It works for a
HUD but is a dead end for the long-term vision:

- Bitmap atlas blurs when scaled up, aliases when scaled down.
- Only alpha coverage — no distance field, so no outline / stroke / glow / shadow.
- Single color per draw, ASCII only, no kerning, no Unicode, no fallback.
- No caching: `Application`, `ShooterGame`, and `ArenaGame` each `Font::Load` the same TTF
  into duplicate atlases.

The target is a modern text system where the renderer never knows whether a font is Bitmap,
SDF, or MSDF; where a central manager caches everything; where MSDF unlocks crisp scaling and
cheap in-shader effects; and where world-space 3D text, rich text, Unicode, and GPU-instanced
glyphs are additive rather than rewrites.

**Non-goals for the design:** committing to a single font technology; implementing all
features at once. The architecture is designed in full here; implementation is phased
(Section 6). Slice 1 is strictly behavior-preserving.

## 2. Guiding principles

- **Backend-agnostic at the seam.** Callers touch only `FontManager`, `FontHandle`,
  `TextStyle`, `TextPlacement`, and `drawText`. Backend choice is *data*, not a vtable.
- **Data-oriented, batch-friendly.** No per-glyph virtual dispatch. Hot-path work is
  batched by render state so mixed backends coexist in one frame.
- **Separation of concerns.** Layout is independent of the render surface; styling is shared
  across surfaces; projection paths are separate from layout and font handling.
- **Additive evolution.** Types and seams (codepoint keys, atlas packer, missing-glyph hook,
  style runs, fallback chain, placement modes) exist from day one; slices fill them in.
- **Low coupling.** Engine core depends only on interfaces. Heavy dependencies (runtime
  `msdfgen`) are optional/compile-flagged providers.

## 3. Architecture Decision Records (locked)

### ADR-1 — Backend polymorphism is data, not a vtable
`FontAsset` is a value/handle carrying a `FontBackend` tag (`Bitmap | SDF | MSDF`), its
`GlyphAtlas`, glyph store, metrics, and a `PipelineHandle`. There is **no** runtime-polymorphic
`Font` base class with per-glyph virtual methods. The common interface is preserved because
callers only ever touch the manager/handle/style/placement API. `TextRenderer` sorts and
**batches by `(surface, backend, atlas, pipeline, effect-flags)`** and binds the right pipeline
once per batch.

**Rejected:** OOP `Font` hierarchy (`BitmapFont`/`SdfFont`/`MsdfFont` subclasses). Literal
reading of "common interface," but per-glyph virtual dispatch fragments batching — each backend
needs a different shader and state — and blocks the GPU-instanced roadmap.

### ADR-2 — Placement abstraction; layout is surface-agnostic
`TextLayout` emits glyph positions in **local text coordinates** only. `TextStyle` is shared
across surfaces. `TextRenderer` consumes a **`TextPlacement` descriptor** that transforms local
coords into the target space via **separate screen-space and world-space projection paths** (no
per-glyph surface branching). Planned modes: `ScreenSpace`, `WorldOriented`, `CameraBillboard`,
`AxisBillboard`. World-text render-state options — depth test/write toggles, transparent
sorting, distance-based vs constant-apparent scaling, HDR/bloom participation, separate UI vs
world passes — are **accommodated in the batch key** but **not implemented in slice 1**. Slice 1
reproduces existing HUD/debug behavior through the new path.

### ADR-3 — Styling split by cadence; per-glyph style index
Style parameters are split by how often they vary:
- **Per-glyph vertex attributes:** `fillColor`, `outlineColor` (packed RGBA), and a reserved
  **`styleIndex`**. These make per-character color, gradients, and rich text work *within a
  single batch* and map directly onto future per-glyph instance data.
- **Per-batch uniforms:** SDF `pxRange`, outline width (distance units), glow/shadow/gradient
  params, effect-enable flags. These define part of the batch key.
- **Rich text** = a string + **style runs** `[range → TextStyle]`. The MVP API takes a single
  `TextStyle` (one full-span run); a markup parser is a later front-end that emits runs.
- `styleIndex` references a **per-batch style table** (UBO/SSBO) so many distinct styles share
  one batch. Backends ignore effect params they cannot honor (graceful degradation).

**Rejected:** one `TextStyle` uniform per draw. Forces per-character color / gradients / rich
text into many draws, defeating batching and smooth gradients.

### ADR-4 — Codepoint glyph identity; static/dynamic atlas; missing-glyph hook
Glyphs are keyed by **`char32_t` codepoint** (`unordered_map<char32_t, Glyph>`), not a fixed
ASCII array. A distinct **glyph-index** concept is reserved now (identity is not permanently
tied to codepoint) for future HarfBuzz-style shaping/kerning. `GlyphAtlas` owns the texture and
a **shelf/skyline packer** and supports two population modes with the same packer:
- **Static** — offline & bitmap paths; fully filled at load, immutable.
- **Dynamic** — runtime path; glyphs inserted **lazily on cache-miss**, atlas grows/re-uploads.

`TextLayout` has a **missing-glyph hook**: MVP returns not-found (`.notdef`/skip, current
behavior); later the hook triggers lazy rasterization or **fallback-font** lookup — no layout
rewrite.

**Rejected:** keep the ASCII `std::array<Glyph,128>` for MVP. Every later goal (Unicode,
emoji, fallback, runtime-lazy) would become a container + layout rewrite.

### ADR-5 — `FontManager` cache + `FontSource` provider seam
`FontManager` is the sole owner/cache; callers hold only a `FontHandle` (or `Ref<FontAsset>`)
and never construct fonts directly. Fonts are loaded by descriptor:

```
FontDesc {
  std::string  family;        // path or family name
  uint32_t     pixelSize;
  FontBackend  backend;       // Bitmap | SDF | MSDF
  SourcePolicy source;        // Offline | Runtime | Auto
  GlyphRange   glyphRange;    // codepoint ranges to bake (offline)
  float        dpiScale;      // reserved (DPI / HiDPI)
  RenderTarget renderTarget;  // reserved (screen vs world/HDR target hints)
}
```

The **normalized `FontDesc` is the cache key**, so identical requests share one `FontAsset`
(eliminating today's duplicate atlases across HUD/shooter/arena).

**`FontSource`** is a small interface — *given a `FontDesc`, produce a `FontAsset`*. Concrete
sources **register** with the manager:
- `BitmapFreeTypeSource` — slice 1 (current FreeType bitmap path).
- `OfflineMsdfSource` — reads a `.png` atlas + `.json` metrics from `msdf-atlas-gen`.
- `RuntimeMsdfSource` — generates via `msdfgen` at load; **optional module / compile flag**.

Engine core depends only on the `FontSource` interface, so `msdfgen` stays an opt-in
dependency. `FontAsset` carries `backend`, `Ref<GlyphAtlas>`, codepoint glyph store, face
metrics (ascent/descent/lineGap), SDF `pxRange`, `PipelineHandle`, and a **fallback chain**
(`vector<FontHandle>`). `FontFamily` groups faces (regular/bold/italic) + the fallback chain;
the types exist in MVP with a single face and empty fallback.

**Rejected:** concrete `switch(backend)` in `FontManager`. Forces engine core to include/link
every backend (incl. `msdfgen`) and prevents compiling out the heavy runtime path.

### ADR-6 — Per-backend shader programs + single-pass in-shader effects; style-table UBO
One focused shader **program per backend** turns *its* atlas into a signed coverage value:
- `bitmap` — samples R8 alpha directly (current behavior).
- `sdf` — `smoothstep` around the 0.5 iso-line using `pxRange`.
- `msdf` — `median(r,g,b)` then the same edge step.

From that coverage, a **shared effect stage composites in a single pass**, front-to-back:
**fill → gradient → N outline layers → glow → drop-shadow** (shadow = offset distance sample;
outline layers use a bounded loop). The bitmap backend has no distance field, so it honors fill
(and per-char color/gradient) but **ignores** outline/glow/shadow.

Style params reach the shader via a **style-table UBO/SSBO** indexed by the per-glyph
`styleIndex`, so rich text with many styles renders in **one draw**. `TextPipeline` =
`{ program, blend state, backend params }`, cached in `TextRenderer` and referenced by
`FontAsset::PipelineHandle`.

**Rejected:** a monolithic übershader with `#define`/branches. Large branchy fragment shader,
awkward to optimize, and backend switches still reconfigure state — losing the clean batch
story. **Rejected:** multi-pass glow/shadow for slice-3 MVP; single-pass keeps batching intact
(a separate blurred glow pass may be revisited if softness is insufficient).

### ADR-7 — Slice 1 is behavior-preserving
Slice 1 registers only `BitmapFreeTypeSource`, ships only the bitmap program behind the new
structure, populates only static ASCII, and **migrates HUD/shooter/arena to the new API while
deleting the old `drawText` path**. The screen output is identical. All seams (vertex format,
style table, pipeline, placement, codepoint store, missing-glyph hook) are in place from day
one so later slices are additive.

## 4. Component map

```
                      +--------------------------------------+
   callers ---------> | TextRenderer  (batch, sort, draw)    |
 (drawText/           |  - TextPlacement -> surface path     |
  drawText3D)         |  - TextPipeline cache                |
                      +---------------+----------------------+
                                      | consumes handles + laid-out glyphs
        +--------------+--------------+------------------+
        v              v              v                  v
   +---------+  +------------+  +----------+     +--------------+
   |FontMgr  |  | TextLayout |  |TextStyle |     | Style table  |
   | (cache) |  |(local crds)|  |(shared)  |     |  (UBO/SSBO)  |
   +----+----+  +-----+------+  +----------+     +--------------+
        | owns        | reads glyph metrics + missing-glyph hook
        v             |
   +---------+        |
   |FontAsset|<-------+   backend tag, pxRange, metrics, PipelineHandle, fallback
   |  +------+---+
   |  |GlyphAtlas|  texture + shelf packer (static | dynamic)
   |  +----------+
   +-- built by ->  FontSource (interface)
                     |- BitmapFreeTypeSource   (slice 1)
                     |- OfflineMsdfSource       (later)
                     |- RuntimeMsdfSource       (later, optional)
```

**Proposed file layout** (extends `engine/renderer/text/`):

```
text/
  FontAsset.hpp          (backend-tagged handle; replaces the current Font.hpp role)
  FontManager.hpp/.cpp
  FontDesc.hpp           (descriptor + normalized cache key)
  FontSource.hpp         (interface) + BitmapFreeTypeSource.hpp/.cpp
  GlyphAtlas.hpp/.cpp    (texture + shelf packer, static/dynamic)
  Glyph.hpp              (codepoint store; glyph-index reserved)
  TextStyle.hpp
  TextLayout.hpp/.cpp    (local coords; missing-glyph hook)
  TextPlacement.hpp      (ScreenSpace | WorldOriented | CameraBillboard | AxisBillboard)
  TextRenderer.hpp/.cpp  (batching, pipeline cache, surface paths)
  TextPipeline.hpp
```

### 4.1 Glyph vertex format (fixed now, serves all backends/surfaces)

```
struct TextVertex {
  glm::vec3 pos;          // local text coords; z reserved for world-space
  glm::vec2 uv;           // atlas UV
  uint32_t  fillColor;    // packed RGBA8
  uint32_t  outlineColor; // packed RGBA8
  uint32_t  styleIndex;   // index into per-batch style table (reserved effects)
};
```

The same format serves bitmap / SDF / MSDF, single-color / rich text, screen / world. Slice 1
writes `fillColor` from the draw's `TextStyle`, leaves `outlineColor`/`styleIndex` at defaults.

## 5. End-to-end data flow (slice 1, screen-space)

```
game/app
  |- font = FontManager.load(FontDesc{path, size=32, backend=Bitmap})   // cached
  |- renderer.drawText(font, "Score", ScreenSpace{x,y,scale}, style)
        |
        v TextRenderer
   1. TextLayout(glyphStore, "Score") -> local glyph quads (advance; missing -> skip)
   2. TextPlacement (ScreenSpace path): local -> pixel -> NDC
   3. emit TextVertex {pos, uv, fillColor, outlineColor=def, styleIndex=0}
   4. push into batch keyed by (surface=Screen, backend=Bitmap, atlas, pipeline, fx=none)
        |
        v endFrame (after composite, as today)
   5. per batch: bind TextPipeline(bitmap program), bind atlas, upload style-table UBO, draw.
      bitmap program: alpha = atlas.r; honors fillColor; ignores outline/glow.
```

## 6. Slice roadmap

Each slice is one engine version with its own plan and is independently shippable.

- **Slice 1 — `v0.28` foundation (behavior-preserving).** `FontManager`, `FontDesc` + cache,
  `FontSource` / `BitmapFreeTypeSource`, `FontAsset`, codepoint `GlyphAtlas` (static/ASCII),
  `TextStyle` (fill only), `TextLayout` (local coords + hook), `TextRenderer` with the
  `ScreenSpace` path, new vertex format, style-table UBO, and bitmap `TextPipeline`. Migrate
  HUD/shooter/arena; delete the old path. Same pixels on screen.
- **Slice 2 — SDF + offline MSDF.** `OfflineMsdfSource`, SDF/MSDF programs, `pxRange`. Crisp
  scaling at any size.
- **Slice 3 — Effects.** Outline (N layers), cartoon stroke, glow, shadow, gradient —
  single-pass compositing via the style table. (The cartoon-stroke/outline goal lands here.)
- **Slice 4 — Rich text & color.** Style runs, per-char color, markup front-end.
- **Slice 5 — Runtime MSDF.** `RuntimeMsdfSource` (optional `msdfgen`), dynamic atlas,
  lazy-on-miss population.
- **Slice 6 — World-space 3D text.** Remaining placement modes, world render-state options,
  HDR/bloom participation, UI vs world passes.
- **Later.** Unicode ranges, fallback fonts, families, kerning/shaping (glyph-index →
  HarfBuzz), GPU-instanced glyph rendering.

## 7. Testing strategy

- Extend `tests/test_text_layout.cpp`: layout in **local coords** — advances, missing-glyph
  skip, baseline placement.
- New unit tests: `FontDesc` cache-key equality/dedup; `GlyphAtlas` shelf packer (placement,
  row wrap, no overlap, atlas-width wrap); `TextStyle` defaults.
- **Slice-1 acceptance:** HUD/shooter/arena render identically (visual check + existing test
  suite green); no duplicate atlases (one `FontAsset` shared for identical `FontDesc`).

## 8. Risks & mitigations

- **Scope creep into a rewrite.** Mitigated by ADR-7: slice 1 is behavior-preserving and small;
  every later capability is a registered provider or an additive stage.
- **Style-table UBO size / cross-platform limits.** Keep the per-style struct compact; fall
  back to SSBO where many styles are needed; cap styles per batch and split batches beyond it.
- **Vertex-format churn.** Mitigated by fixing the format now (Section 4.1) with reserved
  `outlineColor`/`styleIndex` and a `z` channel for world-space.
- **Optional `msdfgen` coupling.** Mitigated by ADR-5: it is a registered provider behind a
  compile flag; engine core depends only on `FontSource`.

## 9. Open items (deferred, not blocking slice 1)

- Exact style-table struct layout and UBO vs SSBO threshold (decided in slice 3).
- Offline atlas file format details / `msdf-atlas-gen` invocation (decided in slice 2).
- Markup grammar for rich text (decided in slice 4).
- World-pass ordering vs bloom (decided in slice 6).

# Engine v0.18 — Engine Debug HUD — Design Spec

**Date:** 2026-07-02
**Status:** Approved for planning
**Scope:** An F1-toggled multi-line on-screen debug HUD (built on the v0.17 text
renderer) showing frame timing, camera, renderer, and JobSystem stats — with the
JobSystem and Renderer instrumentation needed to feed it.
**Builds on:** v0.17 text rendering (merged to `main`). A renderer/tooling milestone.

## 1. Goal & Motivation

The v0.17 overlay shows only FPS. This milestone turns it into an engine debug HUD:
frame time, camera pose, renderer draw/light/lane counts, and JobSystem load —
including per-lane batch distribution, so you can see how well the job system spreads
work. App-level, so both games get it with no game-code changes.

## 2. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Placement | App-level multi-line text (top-left), replaces the standalone FPS line |
| Toggle | `F1` (edge-detected via `Input::wasKeyPressed`); default ON (screenshots show it) |
| Camera line | Generic **position + forward** (from `CameraUniforms`); controller mode (orbit/fly) is game-owned, out of scope |
| Draw count | `m_merged.size()`, read before `endFrame` merges → 1-frame lag (standard for a HUD) |
| JobSystem counters | Plain (no atomics): each lane writes only its own slot; totals written by the main thread only |
| Tested core | `formatDebugLines(const DebugStats&)` — pure, header-only |
| DoD | Both games show the multi-line HUD; `F1` toggles it |

## 3. Instrumentation

### 3.1 `JobSystem::Stats`

```cpp
struct Stats {
  size_t dispatches = 0;             // parallelFor calls this frame
  size_t batches = 0;                // total batches created
  size_t items = 0;                  // total items processed
  std::vector<size_t> laneBatches;   // batches run per lane (size == workerCount())
};
const Stats& stats() const;
void resetStats();  // zeros counters, keeps laneBatches sized to workerCount()
```

`laneBatches` is sized to `m_workerCount` in the constructor. In `parallelFor` (main
thread, before dispatch): `dispatches++`, `batches += batchCount`, `items += count`.
Each executed batch increments `laneBatches[lane]` — workers (`workerLoop`, lanes
1..n) and the main drain loop (lane 0) each touch only their own index, so there is
no data race and no lock is needed. `resetStats` runs at frame start while workers are
idle (between `parallelFor` calls). No behavior change to scheduling.

### 3.2 `Renderer::RenderStats`

```cpp
struct RenderStats {
  size_t drawCount = 0;      // m_merged.size()
  int pointLights = 0;       // m_pointLightCount
  size_t laneCount = 0;      // m_lanes.size()
  glm::vec3 cameraPos{0.0f};
  glm::vec3 cameraFwd{0.0f, 0.0f, -1.0f};
};
RenderStats stats() const;
```

`cameraPos = glm::vec3(m_camera.cameraPosition)`;
`cameraFwd = glm::normalize(-glm::vec3(glm::inverse(m_camera.view)[2]))`.

### 3.3 `Key::F1`

Add `F1` to the `engine::Key` enum and map `SDLK_F1 -> Key::F1` in `SdlWindow`'s
`mapKey`.

## 4. HUD

### 4.1 `DebugStats` + `formatDebugLines` (`engine/core/DebugOverlay.hpp`, header-only)

```cpp
struct DebugStats {
  int fps = 0;
  float frameMs = 0.0f;
  int width = 0, height = 0;
  glm::vec3 cameraPos{0.0f};
  glm::vec3 cameraFwd{0.0f};
  size_t drawCount = 0;
  int pointLights = 0;
  size_t laneCount = 0;
  size_t jobDispatches = 0, jobBatches = 0, jobItems = 0;
  std::vector<size_t> laneBatches;
};

std::vector<std::string> formatDebugLines(const DebugStats& s);
```

Produces exactly these lines (floats via `snprintf("%.1f")`):

```
FPS: <fps> (<frameMs> ms)
Res: <w>x<h>
Cam: (<x>, <y>, <z>)
Fwd: (<x>, <y>, <z>)
Draws: <drawCount>
Lights: <pointLights>
Lanes: <laneCount>
Jobs: <disp> disp / <batch> batch / <items> items
LaneBatches: <b0> <b1> ...
```

Pure, GL/EnTT-free — the unit-test anchor.

### 4.2 `Application`

`bool m_showDebug = true`. Per frame: `m_jobs->resetStats()` after `pollEvents`
(before the layers run their parallel mesh generation); `if
(Input::wasKeyPressed(Key::F1)) m_showDebug = !m_showDebug`. After the layers'
`onRender` and before `endFrame`, build a `DebugStats` from the smoothed FPS, the
window size, `m_renderer->stats()`, and `m_jobs->stats()`; if `m_showDebug`, draw each
`formatDebugLines` entry at `(8, 24 + i*20)`, white, scale 1. This **replaces** the
v0.17 standalone FPS `drawText` (FPS is now line 1 of the HUD).

## 5. Testing

- **Unit (Catch2, no GL):**
  - `formatDebugLines` — exact expected lines for a known `DebugStats` (FPS/ms line,
    the integer lines, `LaneBatches` joins the per-lane counts) and the expected line
    count.
  - Extend `test_job_system`: after `resetStats()` + `parallelFor(100, 10, fn)`,
    assert `stats().dispatches == 1`, `stats().items == 100`, `stats().batches == 10`,
    and the sum of `laneBatches == 10`.
- **Behavioral:** `bot_arena` and `arena_game` screenshots show the multi-line HUD
  (FPS + Res + Cam/Fwd + Draws/Lights/Lanes + Jobs/LaneBatches).

## 6. Out of scope (later)

GPU/pass timings, plots/graphs, memory (arena/pool bytes), the game-specific
camera-controller mode, min/max history, and configurable HUD layout. This milestone
is the HUD + JobSystem/Renderer instrumentation.

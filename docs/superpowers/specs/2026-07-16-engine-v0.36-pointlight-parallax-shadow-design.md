# Engine v0.36 — Point-Light Parallax Self-Shadows — Design Spec

**Date:** 2026-07-16
**Status:** Approved for planning
**Scope:** Extend v0.35's parallax self-shadow (directional light only) to point lights, packed into the spare channels of the existing `gShadow` g-buffer target, consumed by the point-light loop in the deferred lighting pass. A new `parallax_light_demo` game shows a parallax brick floor with a point light orbiting low, sweeping mortar self-shadows.
**Builds on:** the deferred renderer on `main` (v0.28–v0.35 merged; POM + directional parallax self-shadow already present).

## 1. Goal & Motivation

v0.35 computes a parallax self-shadow in the geometry pass against the single directional light and writes it to `gShadow.r`, which the lighting pass folds into the directional term. Point lights — often the dominant near light in a scene — cast no such self-shadow, so raised detail near a point light looks flat-lit in the crevices. This slice marches the self-shadow toward the nearest point lights too and attenuates their contribution, at no cost to non-parallax materials.

## 2. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Packing | Reuse the existing `RGBA8 gShadow` target: `.r` = directional (unchanged), `.g/.b/.a` = the first `min(3, u_pointCount)` point lights (by UBO index). No new g-buffer target |
| Light source in geometry pass | The **existing PointLights UBO (binding 2)** — already uploaded before the geometry pass (`setPointLights` runs in the game's `onRender`, before `endFrame`'s geometry pass) |
| Shadow march | Reuse v0.35's `parallaxShadow(uv, lightT)` verbatim, called per light (directional + up to 3 point lights) |
| Selection | First-3-by-UBO-index (deterministic; the demo controls light order). Lights 4+ get no self-shadow (multiply by 1) |
| Non-parallax default | Non-parallax fragments write `gShadow = vec4(1,1,1,1)` (was `(1,0,0,1)`) so point-light channels default to "fully lit" |
| Lighting pass | Point-light loop multiplies light `i`'s contribution by `gShadow[i+1]` for `i < 3`; `i ≥ 3` by 1. Directional keeps using `.r`. IBL/ambient untouched |
| Demo | New `parallax_light_demo`: a parallax brick **floor**, a point light orbiting **low**, mortar self-shadows sweep as it moves; `BOTARENA_LIGHT=0|1|2` freezes positions |
| Reserved | Nearest-N selection (vs first-N); >3 point lights (2nd target); per-distance shadow softness |

## 3. Components & changes

### 3.1 `mesh.glsl` geometry pass — point-light self-shadow
Add the PointLights UBO (binding 2), matching the lighting shader's block:
```glsl
struct PointLight { vec4 positionRadius; vec4 color; };
layout(std140, binding = 2) uniform PointLights {
    int u_pointCount;
    PointLight u_points[32];
};
```
In `main`, when `u_hasHeight == 1`, after POM produces `uv`, compute the directional self-shadow (→ `.r`, as today) and, for the first `min(3, u_pointCount)` point lights, march toward each:
```glsl
vec4 selfShadow = vec4(1.0);                          // r=dir, gba=points 0..2
if (u_hasHeight == 1) {
    // ... POM produces uv ...
    vec3 lightT = normalize(transpose(TBN) * normalize(u_lightDir.xyz));
    selfShadow.r = parallaxShadow(uv, lightT);
    int np = min(u_pointCount, 3);
    for (int i = 0; i < np; ++i) {
        vec3 Lw = normalize(u_points[i].positionRadius.xyz - v_worldPos);
        vec3 Lt = normalize(transpose(TBN) * Lw);
        selfShadow[i + 1] = parallaxShadow(uv, Lt);
    }
}
gShadow = selfShadow;   // non-parallax path leaves it (1,1,1,1)
```
`parallaxShadow` is unchanged from v0.35. The whole block stays gated behind `u_hasHeight`; non-parallax materials write `vec4(1.0)`.

### 3.2 Lighting pass — consume point-light channels
In the inline lighting fragment shader (`OpenGLBackend`), sample `gShadow` once and attenuate the first three point lights in the existing loop:
```glsl
vec4 pShadow = texture(u_gShadow, v_uv);
// ... directional: * (1.0 - pcfShadow) * pShadow.r  (unchanged) ...
for (int i = 0; i < u_pointCount; ++i) {
    // ... existing radiance / attenuation ...
    float ps = i < 3 ? pShadow[i + 1] : 1.0;
    color += brdf(N, V, Lp, albedo, metallic, rough, F0, radiance) * ps;
}
```
No `lightingPass` signature change — `gShadow` (unit 9) is already bound and sampled for the directional term; this reads the other channels.

### 3.3 New demo `parallax_light_demo`
`parallaxlightdemo::ParallaxLightDemoGame` (`parallax_light_demo_game` target), like the other games:
- A large **parallax brick floor** (scaled cube, `brick_d.jpg` + `brick_n.jpg` + `brick_h.png`, `heightScale ≈ 0.08`), lying flat (top `+Y` face up).
- One bright **point light orbiting low** over the floor (small height, radius large enough to reach), so the mortar self-shadows stretch and sweep as it moves. Shown as an emissive billboard (the engine already draws point-light billboards).
- The directional light is dimmed to near-neutral (e.g. pointing straight down, or low intensity) so the point light is unmistakably the caster.
- `BOTARENA_LIGHT=0|1|2` freezes the orbiting light at a few positions for before/after screenshots; it orbits over time otherwise.
- Camera looks **down at an oblique angle** so the floor relief and its sweeping shadows read.
- Optional SDF HUD label (e.g. "point-light parallax shadows"); billboard/world text is available but not required.

## 4. Data flow

```
mesh + Material{..., heightMap}
  -> executeGeometry: bind height(2); PointLights UBO (binding 2) already uploaded
  -> mesh.glsl geometry pass (u_hasHeight):
       POM -> uv
       parallaxShadow(uv, dirLightT)         -> gShadow.r
       parallaxShadow(uv, pointLightT[i])    -> gShadow.g/b/a   (first 3 points)
     non-parallax -> gShadow = (1,1,1,1)
  -> lighting pass:
       directional *= (1 - pcfShadow) * gShadow.r         (v0.35)
       point light i *= (i<3 ? gShadow[i+1] : 1.0)        (new)
       IBL/ambient untouched
```

## 5. Testing

- **Screenshot-validated** (consistent with the rest of the renderer): `parallax_light_demo` across the `BOTARENA_LIGHT` presets shows mortar self-shadows on the floor that sweep to follow the orbiting point light — the defining proof this is a *point-light* self-shadow, not the directional one.
- **Regression:** existing games (arena/shooter/camera/billboard/text/normalmap) have `heightMap == null` → `u_hasHeight == 0`, so they write `gShadow = vec4(1,1,1,1)` and every light term multiplies by 1 — no visual change. `normalmap_demo`'s directional self-shadow still uses `.r` unchanged. Shooter/arena/normalmap screenshots stay identical; full build + suite green.
- **Correctness of the default:** the non-parallax `gShadow` default changes from `(1,0,0,1)` to `(1,1,1,1)`; without this, point lights 0 and 1 would be zeroed on every non-parallax surface — this is the load-bearing regression check.

## 6. Risks & mitigations

- **Non-parallax default zeroing point lights.** The single most important change: non-parallax fragments must write `vec4(1.0)`, not `(1,0,0,1)`. Verified by the shooter/arena regression screenshots (they use point lights).
- **Only 3 point lights shadowed.** Accepted and documented; the demo uses one dominant point light. Lights 4+ multiply by 1.
- **3× extra shadow marches in the geometry pass.** Bounded (16 layers each) and gated behind `u_hasHeight`; only parallax materials pay.
- **Channel/index mismatch** between geometry write (`selfShadow[i+1]`) and lighting read (`pShadow[i+1]`). Mitigation: both use the same `i+1` convention (r=dir, g/b/a=points 0/1/2); stated once here and carried into the plan.
- **PointLights UBO not populated in the geometry pass.** Verified: `setPointLights` uploads binding 2 during `onRender`, before `endFrame`'s geometry pass.

## 7. Open items (deferred, not blocking)

- Nearest-N point-light selection instead of first-N.
- More than 3 shadowed point lights (a 2nd `gShadow` target).
- Per-distance / per-radius softening of the point-light self-shadow.

# Engine v0.30 — SDF Text Effects (Slice 3) — Design Spec

**Date:** 2026-07-15
**Status:** Approved for planning
**Scope:** Add real, single-pass SDF text effects — outline, glow, and drop-shadow — composited in the fragment shader from the distance field, driven by a per-batch style-table UBO indexed by a per-glyph `styleIndex`. This replaces the demo's app-level layered draws with true engine features. Effect sizes are specified in screen pixels and stay scale-correct.
**Builds on:** v0.29 SDF text (branch `feat/engine-v0.29-sdf-text`).
**Design source:** Slice 3 of `docs/superpowers/specs/2026-07-15-engine-v0.28-text-system-architecture-design.md` (ADR-3, ADR-6), realized here.

## 1. Goal & Motivation

v0.29 shipped crisp SDF fill and the `pxRange` seam. Slice 3 consumes that seam to render
outline (which yields cartoon and colored-stroke looks), outer glow, and drop-shadow in a single
draw, replacing the `text_demo`'s app-level layering (nine draws per string, chunky corners) with
one smooth, scale-correct pass. This delivers the effects the user asked for as real engine
capabilities.

Because batches merge by `(backend, atlas)`, two `drawText` calls with the same font but
different styles already share one batch. Per-glyph colors are already vertex attributes, but
non-color effect params (widths, glow, shadow) cannot be — so a **per-batch style-table UBO
indexed by a per-glyph `styleIndex`** carries them (ADR-3/ADR-6). This is what lets one batch
draw plain and outlined+glowing text in a single draw.

## 2. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Effects | Fill + **outline** (1 layer) + **glow** (outer) + **drop-shadow**, single-pass |
| Deferred | Gradient fill, multi-layer outlines (N>1), rich text / per-char styles (Slice 4), MSDF |
| Effect units | **Screen pixels** (e.g. 2 px outline), made scale-correct via the MSDF `screenPxRange` derived from `pxRange` + `fwidth` |
| Style params delivery | Per-batch **style-table UBO** (`std140`), indexed by a per-glyph `styleIndex` |
| `styleIndex` | **Renderer-managed** — `TextRenderer` dedups styles into the table and assigns indices; callers never set it |
| API | `drawText(font, text, placement, style)` unchanged; `TextStyle` gains effect fields (zero = off, so existing callers are unaffected) |
| Table cap | ~64 styles per batch; a batch exceeding it splits |
| Adoption | Bitmap path untouched; SDF path composites effects. The `text_demo` uses the real effects; HUD/shooter/arena unchanged (they use plain styles) |

## 3. Components & changes

### 3.1 `TextStyle` expands (`TextStyle.hpp`)
```cpp
struct TextStyle {
  glm::vec4 fillColor{1.0f};
  glm::vec4 outlineColor{0.0f};   float outlineWidthPx = 0.0f;
  glm::vec4 glowColor{0.0f};      float glowSizePx = 0.0f;
  glm::vec4 shadowColor{0.0f};    glm::vec2 shadowOffsetPx{0.0f};  float shadowSoftnessPx = 0.0f;
  uint32_t styleIndex = 0;        // internal: assigned by TextRenderer, not the caller
};
```
All effect fields default to zero (off). A caller that sets only `fillColor` behaves exactly as
in v0.28/29. Effect widths/sizes/offsets are in screen pixels.

### 3.2 GPU style layout (`std140`)
A `GpuStyle` struct mirrors the per-style data the shader needs, laid out for `std140`:
```
fillColor    (vec4)
outlineColor (vec4)
glowColor    (vec4)
shadowColor  (vec4)
params0      (vec4: outlineWidthPx, glowSizePx, shadowOffsetPx.x, shadowOffsetPx.y)
params1      (vec4: shadowSoftnessPx, pad, pad, pad)
```
6 × `vec4` = 96 bytes/style; 64 styles = 6 KB (well under the UBO min). Lives in a small header
(e.g. `TextStyleGpu.hpp`) or alongside `TextRenderer`.

### 3.3 `TextRenderer` builds the style table
- `Batch` gains `std::vector<GpuStyle> styles;`.
- `submit` converts the call's `TextStyle` to a `GpuStyle` and **dedups by value** into the
  batch's `styles` (returning an existing index or appending a new one), then writes that index
  into every emitted glyph vertex's `styleIndex`. Colors continue to be packed per-vertex too
  (bitmap path + future per-char color), but the SDF path reads style from the table.
- If a batch's table would exceed the cap (64), `submit` starts a new batch for the same
  `(backend, atlas)` (a documented split; keyed so subsequent same-style submits reuse it).
- Layout, projection, and vertex emission are otherwise unchanged from v0.29.

### 3.4 Backend: effect compositing + style UBO
- `drawTextBatch` gains the style list:
  `drawTextBatch(FontBackend backend, uint32_t atlasTextureId, const std::vector<TextVertex>& verts, float pxRange, const std::vector<GpuStyle>& styles)`.
- `OpenGLBackend` owns a `Ref<UniformBuffer>` for the style table (created once, `setData` per
  SDF batch) bound to a fixed binding point; the SDF program declares the matching `std140`
  block. Bitmap batches ignore it.
- The **SDF fragment shader** composites single-pass:
  ```
  float d = texture(uAtlas, vUV).r;
  float spr = screenPxRange(uPxRange, uAtlas, vUV);   // scale-correct px range
  float sd  = spr * (d - 0.5);                         // signed screen-px distance
  GpuStyle s = styles[vStyleIndex];
  float fill    = clamp(sd + 0.5, 0.0, 1.0);
  float body    = clamp(sd + s.outlineWidthPx + 0.5, 0.0, 1.0);   // fill + outline extent
  float outline = body - fill;
  float glow    = clamp((sd + s.outlineWidthPx + s.glowSizePx) / max(s.glowSizePx, 1.0), 0.0, 1.0) * (1.0 - body);
  // shadow: sample the field offset by the shadow's screen-px offset (→ UV via fwidth)
  vec2 sUV = vUV - s.shadowOffsetPx * fwidth(vUV);
  float sdS = spr * (texture(uAtlas, sUV).r - 0.5);
  float shadow = smoothstep(-s.shadowSoftnessPx, s.shadowSoftnessPx, sdS) * (1.0 - body);
  // composite back-to-front, output straight alpha for SRC_ALPHA blending
  vec4 c = vec4(0.0);
  c = over(c, s.shadowColor  * shadow);
  c = over(c, s.glowColor    * glow);
  c = over(c, s.outlineColor * outline);
  c = over(c, s.fillColor    * fill);
  FragColor = c;
  ```
  (`screenPxRange` and `over` are small helpers; exact math finalized in the plan. Values are
  clamped and guarded against divide-by-zero when an effect size is 0.)
- `Renderer::endFrame` forwards `b.styles` to `drawTextBatch`.

### 3.5 Demo (`games/text_demo`)
Replace the app-level `drawShadow`/`drawOutline` helpers with real single-pass effects: build a
`TextStyle` with `outlineColor/outlineWidthPx`, `glowColor/glowSizePx`, and
`shadowColor/shadowOffsetPx/shadowSoftnessPx`, and `drawText` once per label. Show cartoon (thick
dark outline + flat fill), colored stroke, outer glow, and drop-shadow — now smooth at any scale.
Keep the SDF-vs-bitmap comparison. Update the footer to note real single-pass SDF effects.

## 4. Data flow

```
demo: drawText(sdfFont, "WARNING", ScreenSpace{...}, TextStyle{fill, outline, glow, shadow})
  -> TextRenderer.submit:
       gpu = toGpuStyle(style)
       idx = batch.styles dedup-insert(gpu)          // per-batch style table
       emit glyph verts with styleIndex = idx
  -> endFrame: drawTextBatch(SDF, atlas, verts, pxRange, batch.styles)
  -> OpenGLBackend: upload styles to UBO, bind; sdf program composites
       shadow -> glow -> outline -> fill (single pass, screen-px scale-correct)
```
Bitmap path unchanged; plain SDF styles (all effects zero) render as crisp fill exactly as v0.29.

## 5. Testing

- **`TextRenderer` style table (CPU, the design payoff):** equal `TextStyle`s dedup to one entry
  and share a `styleIndex`; distinct styles get distinct entries/indices; each glyph vertex
  carries the correct `styleIndex`; exceeding the cap splits the batch. No GL.
- **`GpuStyle` conversion:** `toGpuStyle` packs `TextStyle` fields into the `std140` layout
  correctly (field values/positions).
- **Effect compositing:** GL, screenshot-verified (controller inspects outline/glow/shadow/
  cartoon rendered single-pass, smooth at large scale; corners cleaner than the old layering).
- **Regression:** existing text tests green; bitmap HUD/shooter/arena unchanged; plain SDF text
  (no effects) identical to v0.29.

## 6. Risks & mitigations

- **std140 layout mismatch** between `GpuStyle` and the shader block → garbled effects. Mitigation:
  keep the struct to whole `vec4`s (no straddling), unit-test the packing, and verify visually.
- **Divide-by-zero / NaN** when an effect size is 0. Mitigation: guard denominators
  (`max(size, 1.0)`) and gate each effect on a positive size.
- **Shadow offset scale-correctness.** Mitigation: convert screen-px offset to UV via
  `fwidth(vUV)`; verify the shadow tracks the glyph at 1× and 3×.
- **Batch style-cap splitting** could surprise. Mitigation: cap at 64, document, and `log` when a
  split occurs; unit-test the boundary.
- **`drawTextBatch` signature change** ripples to `RenderBackend`/`OpenGLBackend`/`Renderer` — one
  mechanical change, `OpenGLBackend` is the only subclass.

## 7. Open items (deferred, not blocking)

- Gradient fill and multi-layer outlines (additive `TextStyle` fields + shader stages on the same
  UBO seam).
- Rich text / per-character styles (Slice 4) — per-char `styleIndex` assignment and table growth.
- MSDF backend (optional, `msdfgen`).
- Inner effects (inner shadow / inner glow), if ever needed.

# Engine v0.20 — Particle System & Demo Game — Design Spec

**Date:** 2026-07-02
**Status:** Approved for planning
**Scope:** A CPU particle system (pooled simulation + 3 emit presets), an additive
instanced billboard renderer that glows via bloom, and a new `particles_game`
executable demoing burst-on-collision, a fountain, and a smoke column — leaving
`bot_arena` and `arena_game` untouched.
**Builds on:** the deferred renderer's emissive-billboard/bloom path and
`resolveWallBounce`, on `main`. Renderer + third game example.

## 1. Goal & Motivation

The engine has no particle effects. v0.20 adds a reusable CPU particle system and
renders it as additive camera-facing billboards into the HDR scene (before bloom), so
particles glow. A new game example demonstrates ≥3 effect types — a burst on every
wall collision, a continuous fountain, and a rising smoke column — proving the
particle system on the shared engine library without touching the existing games.

## 2. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Simulation | CPU, pooled `std::vector<Particle>`; per-particle position/velocity/color/gravity/size/life |
| Rendering | Instanced camera-facing quads, **additive into the HDR scene before bloom** (mirrors `drawLightBillboards`) → particles bloom |
| Presets (≥3) | Burst (radial, warm, gravity, short) — collision-triggered; Fountain (upward cone, bright, additive); Smoke (slow rise, grows, grey, long) |
| Demo | New `particles_game` under `games/particles/`, linking `bot_arena_engine`; `bot_arena`/`arena_game` untouched |
| Tested core | `integrateParticle` / `lifeFraction` / `renderColor` / `isDead` and `ParticleSystem::update`/`emit` (pure, no GL) |
| DoD | `particles_game` screenshot shows glowing fountain + smoke + a collision burst |

## 3. Particle simulation (`engine/particles/`)

`Particle.hpp` (header-only, pure):

```cpp
struct Particle {
  glm::vec3 position{0.0f};
  glm::vec3 velocity{0.0f};
  glm::vec3 color{1.0f};
  glm::vec3 gravity{0.0f};
  float size = 0.1f;
  float life = 0.0f;
  float maxLife = 1.0f;
};

inline Particle integrateParticle(Particle p, float dt, glm::vec3 gravity) {
  p.velocity += gravity * dt;
  p.position += p.velocity * dt;
  p.life -= dt;
  return p;
}
inline float lifeFraction(const Particle& p) {
  if (p.maxLife <= 0.0f) return 0.0f;
  return std::clamp(p.life / p.maxLife, 0.0f, 1.0f);
}
inline glm::vec3 renderColor(const Particle& p) {
  return p.color * lifeFraction(p);  // fades to black as it dies
}
inline bool isDead(const Particle& p) { return p.life <= 0.0f; }
```

`ParticleSystem.{hpp,cpp}`:

```cpp
struct EmitParams {
  int count = 0;
  float speedMin = 0.0f, speedMax = 0.0f;
  glm::vec3 direction{0.0f};  // base dir; length 0 => fully radial
  float spread = 1.0f;        // jitter added to the base direction
  glm::vec3 color{1.0f};
  float sizeMin = 0.1f, sizeMax = 0.1f;
  float lifeMin = 1.0f, lifeMax = 1.0f;
  glm::vec3 gravity{0.0f};
};

class ParticleSystem {
 public:
  void emit(const EmitParams& p, const glm::vec3& origin, std::mt19937& rng);
  void update(float dt);  // integrate each by its gravity, remove dead
  const std::vector<Particle>& particles() const { return m_particles; }
  std::size_t size() const { return m_particles.size(); }
  void clear() { m_particles.clear(); }
 private:
  std::vector<Particle> m_particles;
};
```

`emit`: for `count` particles, `dir = normalize(direction + spread * randUnit(rng))`
(if that is ~0, use `randUnit`); `velocity = dir * rand(speedMin,speedMax)`; sample
size/life from their ranges; push `{origin, velocity, color, gravity, size, life,
life}`. `update`: `p = integrateParticle(p, dt, p.gravity)` for all, then
`erase(remove_if(isDead))`.

## 4. Renderer path

`engine/renderer/ParticleInstance.hpp`:

```cpp
struct ParticleInstance {
  glm::vec3 position;
  float size;
  glm::vec4 color;  // rgb pre-faded; a = 1
};
```

- **Backend** `drawParticles(const ParticleInstance* data, int count)` — a new inline
  particle program (billboard vs using `u_view` right/up + `u_viewProjection`, per-
  instance `a_center`/`a_size`/`a_color`; fs: `color.rgb * smoothstep(1,0,
  length(local)) * color.a`), additive (`GL_ONE, GL_ONE`), depth off. Instanced VAO:
  binding 0 = the existing unit quad (`m_quadVbo`, loc 0), binding 1 = a dynamic
  instance VBO (loc 1 `vec3` pos, loc 2 `float` size, loc 3 `vec4` color, divisor 1).
  `glDrawArraysInstanced(GL_TRIANGLE_STRIP, 0, 4, count)`.
- **Renderer** — `submitParticles(const std::vector<ParticleInstance>&)` appends to a
  per-frame buffer (cleared in `beginFrame`); `endFrame` calls `drawParticles` right
  after `drawLightBillboards` (scene FBO still bound, before bloom).

## 5. Demo game (`games/particles/`)

`particles_game` (executable) = `main.cpp` + `ParticlesGame.{hpp,cpp}`, linking
`bot_arena_engine`. Scene: a ground plane and a few cube "emitter" objects bouncing
inside a box (reusing `resolveWallBounce`). Systems (fixed-timestep, like the arena):

- **Burst on collision** — when `resolveWallBounce` changes a bouncer's velocity, `emit`
  a `kBurst` preset at the contact point (warm radial spray, gravity, short life).
- **Fountain** — a fixed central emitter runs `kFountain` every step (bright upward cone).
- **Smoke** — a fixed emitter runs `kSmoke` every step (grey, slow rise, grows, long life).

`onRender` submits every live particle from the systems as `ParticleInstance{position,
size, vec4(renderColor(p), 1)}` and draws the bouncers + ground via `MeshRenderer`.
Orbit camera; a deterministic warm-up so the capture shows particles in flight.

## 6. Testing

- **Unit (Catch2, no GL):** `integrateParticle` (gravity + position step + life
  decrement), `lifeFraction`/`renderColor` (full → color, dead → 0), `isDead`;
  `ParticleSystem` — `emit(count)` adds `count`; `update` past `maxLife` removes them;
  a live particle survives and moved.
- **Behavioral:** `particles_game` screenshot shows the glowing fountain, the smoke
  column, and at least one collision burst; `bot_arena`/`arena_game` unchanged.

## 7. Out of scope (later)

GPU/compute particles, textured/animated sprites, soft-particle depth fade, sub-
emitters/trails, particle-vs-scene collision, and an editor. This milestone is a CPU
particle system + 3 presets + collision trigger + the demo game.

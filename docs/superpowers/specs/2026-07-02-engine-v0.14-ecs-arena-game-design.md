# Engine v0.14 — Reusable Engine Library & ECS Arena Game — Design Spec

**Date:** 2026-07-02
**Status:** Approved for planning
**Scope:** Extract the engine into a reusable static library, then build a **second**
game on it — an ECS-driven arena with a fixed-timestep simulation, an input-driven
player, and wandering bots that bounce off the walls. The existing `BotArenaGame`
renderer showcase is preserved unchanged.
**Builds on:** v0.13 (merged to `main`). First gameplay milestone (pivot from the
renderer arc).

## 1. Goal & Motivation

The renderer is a complete deferred-PBR pipeline, but "Bot Arena" has no game: no
ECS, no simulation loop, no input-driven entities, no collision. This milestone
establishes the **game half** of the engine and proves the engine is reusable by
standing up a *separate* game that links it.

Two deliverables:

1. **Reusable engine library** — `engine/**` becomes `bot_arena_engine` (static
   lib). Both the existing showcase and the new game link it. This makes "the
   engine" a real, reusable artifact.
2. **ECS arena game** — a new `arena_game` executable: EnTT ECS, a fixed-timestep
   simulation, a WASD player, ~48 wandering bots, AABB wall-bounce collision, all
   drawn by the existing deferred renderer.

`BotArenaGame` (the 2048-cube renderer showcase) is **not modified or deleted** — it
remains the rendering demo; `arena_game` is the gameplay demo.

## 3. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Engine artifact | `add_library(bot_arena_engine STATIC …)` from all `engine/**` sources; deps/includes/`BOTARENA_ASSET_DIR` exposed PUBLIC |
| `bot_arena` | Unchanged behavior: `src/main.cpp` + `game/BotArenaGame.cpp`, links the engine lib |
| New game | `games/arena/` (`ArenaGame` + `main.cpp`) → `arena_game` executable, links the engine lib; `namespace arena` |
| Tests | `bot_arena_tests` unchanged + two new header-only helper tests |
| ECS | EnTT `entt::registry` owned by `ArenaGame` |
| Components | `Transform{pos,scale}`, `Velocity{value}`, tags `Player`, `Bot` (in `games/arena/Components.hpp`) |
| Sim loop | Fixed timestep 60 Hz, accumulator in `onUpdate`, max 5 steps/frame (spiral cap); render uses latest transforms (no interpolation) |
| Movement | `pos += vel*dt`; AABB wall-bounce (clamp + reflect) each step |
| Player | WASD → velocity in the arena XZ plane; bounces off walls |
| Bots | ~48, deterministic-seeded random spawn + velocity, constant speed, wander (wall bounce only) |
| Collision | Walls only; **bot-bot deferred** |
| Tested core | `resolveWallBounce(...)` and `fixedTimestep(...)` — pure, header-only, EnTT-free |
| DoD | `arena_game` runs and screenshots a player + ~48 bots inside the arena, positioned by the sim; WASD moves the player |

## 4. Architecture & data flow

```
Application (engine) — per frame:
  onUpdate(dt):   ArenaGame accumulates dt; fixedTimestep() → run N sim steps:
                    input → player Velocity; for each (Transform,Velocity):
                      integrate + resolveWallBounce
  onRender(r):    ArenaGame sets camera + point lights + submits walls/ground,
                  then iterates registry<Transform> → MeshRenderer.submit(cube,
                    material-by-tag, transform)
  r.endFrame():   deferred pipeline draws it (unchanged)
```

## 5. Engine library (CMake refactor)

Replace the monolithic `add_executable(bot_arena <engine + game + main>)` with:

```cmake
add_library(bot_arena_engine STATIC <all engine/** .cpp>)
target_include_directories(bot_arena_engine PUBLIC ${CMAKE_CURRENT_SOURCE_DIR} ${Stb_INCLUDE_DIR})
target_compile_definitions(bot_arena_engine PUBLIC BOTARENA_ASSET_DIR="${CMAKE_CURRENT_SOURCE_DIR}/assets")
target_link_libraries(bot_arena_engine PUBLIC SDL3::SDL3 glad::glad glm::glm EnTT::EnTT
                      spdlog::spdlog yaml-cpp::yaml-cpp imgui::imgui Threads::Threads)

add_executable(bot_arena src/main.cpp game/BotArenaGame.cpp)
target_link_libraries(bot_arena PRIVATE bot_arena_engine)

add_executable(arena_game games/arena/main.cpp games/arena/ArenaGame.cpp)
target_link_libraries(arena_game PRIVATE bot_arena_engine)
```

`bot_arena_tests` stays as-is (it compiles its own small subset of engine sources +
the header-only helpers); no engine-lib link, to avoid destabilizing the passing
suite. `bot_arena`'s build output and runtime behavior are byte-for-byte unchanged
(verified by an identical screenshot).

## 6. Tested core (pure helpers)

`engine/physics/Collision.hpp` (header-only, EnTT-free):

```cpp
struct WallBounce { glm::vec3 position; glm::vec3 velocity; };
inline WallBounce resolveWallBounce(glm::vec3 pos, glm::vec3 vel,
                                    glm::vec3 boundsMin, glm::vec3 boundsMax,
                                    float radius) {
  for (int a = 0; a < 3; ++a) {
    if (pos[a] + radius > boundsMax[a]) {
      pos[a] = boundsMax[a] - radius;
      vel[a] = -std::abs(vel[a]);
    } else if (pos[a] - radius < boundsMin[a]) {
      pos[a] = boundsMin[a] + radius;
      vel[a] = std::abs(vel[a]);
    }
  }
  return {pos, vel};
}
```

`engine/core/FixedTimestep.hpp` (header-only):

```cpp
struct FixedStep { int steps; float remainder; };
inline FixedStep fixedTimestep(float accumulated, float step, int maxSteps) {
  int steps = static_cast<int>(accumulated / step);
  float remainder = accumulated - static_cast<float>(steps) * step;
  if (steps > maxSteps) { steps = maxSteps; remainder = 0.0f; }  // drop backlog
  if (steps < 0) { steps = 0; remainder = accumulated; }
  return {steps, remainder};
}
```

## 7. ECS arena game

- **Components** (`games/arena/Components.hpp`, `namespace arena`): `Transform {
  glm::vec3 position; float scale; }`, `Velocity { glm::vec3 value; }`, empty tags
  `Player`, `Bot`.
- **`ArenaGame : engine::Layer`** owns `entt::registry m_registry`, an
  `OrbitCameraController`, material handles, an accumulator, and a seeded RNG.
  - `onAttach`: configure the camera; spawn 1 player (center) + 48 bots (seeded
    random XZ position + velocity, `y` fixed on the ground) with `Transform`,
    `Velocity`, and their tag. Materials are assigned at render (they need the
    renderer's registry).
  - `onUpdate(dt)`: accumulate; `fixedTimestep(...)` → for each step: read WASD →
    set the player's `Velocity`; then integrate + `resolveWallBounce` every
    `(Transform, Velocity)` against the arena interior bounds.
  - `onRender`: first frame registers materials (player + a bot palette) and the
    arena resources; sets the camera + a few point lights; submits the walls +
    ground; iterates `registry.view<Transform>()` and submits the unit cube with
    the player-or-bot material and the entity transform.
- **`games/arena/main.cpp`**: `Application app; app.pushLayer(make_unique<ArenaGame>());
  app.run();` (mirrors `src/main.cpp`).

Arena interior bounds: `±4.75` in XZ (inside the `±5` walls); agents ride at `y =
0.3`. Fixed step `1/60`, max 5 steps. Player speed ~`3`, bot speed ~`2`.

## 8. Testing

- **Unit (Catch2, no GL, no EnTT):** `resolveWallBounce` (clamps + reflects past
  each wall; leaves interior points untouched) and `fixedTimestep` (0 steps below
  one step; correct count + remainder in the normal case; caps at `maxSteps` and
  drops backlog).
- **Behavioral:** `bot_arena` screenshot is unchanged (lib refactor is inert);
  `arena_game` screenshot shows the player + ~48 bots as distinct cubes inside the
  walled arena, positioned by the simulation (not `botTransform`). Interactive: WASD
  moves the player; agents bounce off the walls.

## 9. Out of scope (later)

Bot-bot collision (O(n²) or broadphase) and its resolution, AI behaviours, combat/
health, camera-follow, a shared "arena scene" abstraction between the two games
(kept as light duplication for now), and the deferred renderer items (`.hdr`, light
culling). This milestone is the engine-library extraction + the minimal simulated
arena.

# Engine v0.25 — Top-Down Space Shooter (Core) — Design Spec

**Date:** 2026-07-02
**Status:** Approved for planning
**Scope:** A new `shooter_game` — a top-down space shooter's first playable slice: fly
the player ship, auto-fire projectiles, enemy ships spawn and seek the player, and
projectile hits destroy enemies for score. Reuses the ECS/sim/steering/model stack.
**Builds on:** v0.24 (models + materials), v0.22 loader, v0.16 steering, v0.17 text,
v0.14 fixed-timestep — all on `main`. Fifth game example.

## 1. Goal & Motivation

A capstone game that combines the engine: EnTT + fixed-timestep, steering, collision,
model loading, and a text HUD. This first slice is the core loop — fly, shoot, enemies
converge, kills score. Health/enemy-fire, explosions, waves, and asteroids are
follow-up milestones.

## 3. Decisions (locked)

| Decision | Choice |
| --- | --- |
| View | Top-down orbit camera over the XZ plane (like the arena) |
| Player | WASD moves (direct velocity, faces heading); **auto-fires** forward on a cooldown |
| Enemies | 3 tiers (model + speed); spawn at edges on a timer (cap ~12); `seek` the player |
| Bullets | Spawn at the ship nose along its heading; live ~2 s / until a hit / until out of bounds |
| Hits | Bullet–enemy circle overlap → both removed; `score += tier weight` (1/2/3) |
| Breach | An enemy reaching the player is removed and increments `leaks` (no player health yet) |
| Tested core | `headingToYaw` / `forwardFromYaw` / `circlesOverlapXZ` (pure) |
| HUD | `Score`, `Leaks`, `Enemies` via the v0.17 text renderer |
| DoD | The screenshot shows the Viper firing, enemy ships converging, and a non-zero score |

## 4. Pure core (`engine/gameplay/ShipControls.hpp`)

```cpp
// Yaw (radians about +Y) so a +Z-forward model points along v (XZ). v~0 -> 0.
float headingToYaw(const glm::vec3& v);       // atan2(v.x, v.z)
glm::vec3 forwardFromYaw(float yaw);          // (sin(yaw), 0, cos(yaw))
bool circlesOverlapXZ(const glm::vec3& a, float ra,
                      const glm::vec3& b, float rb);  // XZ distance < ra+rb
```

`forwardFromYaw(headingToYaw(v))` returns `normalize(v.xz)`.

## 5. Components (`games/shooter/Components.hpp`)

```cpp
struct Transform { glm::vec3 position{0}; float scale{0.5f}; float yaw{0}; };
struct Velocity { glm::vec3 value{0}; };
struct Player {};                 // tag
struct Enemy { int tier = 0; };   // 0 grunt / 1 heavy / 2 elite
struct Bullet { float life = 0.0f; };
```

## 6. Simulation (`ShooterGame::stepSim`, fixed 60 Hz)

1. **Input → player**: WASD → `velocity = normalize(dir)*kPlayerSpeed`; if moving,
   `yaw = headingToYaw(velocity)`.
2. **Auto-fire**: `m_fireTimer -= dt`; when ≤ 0, spawn a `Bullet` at `playerPos +
   forwardFromYaw(yaw)*kNoseOffset`, velocity `forwardFromYaw(yaw)*kBulletSpeed`,
   `life = kBulletLife`; reset the timer to `kFireCooldown`.
3. **Enemy steering**: each enemy `seek`s the player (v0.16), accelerates, clamps to its
   tier speed; `yaw = headingToYaw(velocity)`.
4. **Spawn**: `m_spawnTimer` → spawn an enemy on a random edge with a random tier
   (weighted grunt-heavy) while `enemyCount < kEnemyCap`.
5. **Integrate**: `position += velocity*dt` for all; bullets also `life -= dt`.
6. **Hits**: for each bullet × enemy, `circlesOverlapXZ` (bullet radius + enemy radius)
   → destroy both, `m_score += weight[tier]`.
7. **Cleanup**: remove bullets with `life ≤ 0` or out of bounds; remove enemies that
   `circlesOverlapXZ` the player → `m_leaks++`.

The deterministic warm-up (~150 steps, no input) has enemies spawn + converge while the
idle player auto-fires forward, so the capture shows action and a starting score.

## 7. Rendering (`ShooterGame::onRender`)

Load the five models (player, 3 enemy tiers, bullet) on the first frame via
`loadModel(assetPath(...), registry, meshShader)`; load a font. Render each entity as
`translate(pos) * rotateY(yaw) * scale(shipScale) * fitToUnitTransform(model.bounds)`
with the model's sub-mesh materials, on a dark ground plane, under an orbit camera + a
key light. (A per-model yaw offset constant corrects any model whose forward isn't +Z —
tuned by screenshot.) The HUD draws `Score`/`Leaks`/`Enemies` bottom-left.

## 8. Testing

- **Unit (Catch2, pure):** `headingToYaw` (+Z→0, +X→π/2, −Z→π), `forwardFromYaw`
  (0→+Z, π/2→+X), the round-trip, and `circlesOverlapXZ` (overlap / separated / y
  ignored).
- **Behavioral:** `shooter_game` screenshot shows the Viper firing a stream of bullets,
  enemy ships converging, and `Score > 0`; other games unchanged.

## 9. Out of scope (follow-up milestones)

Player health/lives + game-over, enemy fire, explosions (particles on kills), waves +
win/lose, asteroids as destructible obstacles, power-ups, and mouse aim.

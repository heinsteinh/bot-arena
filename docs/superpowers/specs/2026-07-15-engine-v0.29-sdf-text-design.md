# Engine v0.29 — SDF Text (Slice 2) — Design Spec

**Date:** 2026-07-15
**Status:** Approved for planning
**Scope:** Add a single-channel signed-distance-field (SDF) text backend so text stays crisp at any scale, using FreeType's built-in outline SDF renderer — no new dependencies. SDF is a parallel branch selected by the font's backend tag; the bitmap path is unchanged and remains what the HUD and games use.
**Builds on:** v0.28 text system foundation (branch `feat/engine-v0.28-text-system`).
**Design source:** Slice 2 of `docs/superpowers/specs/2026-07-15-engine-v0.28-text-system-architecture-design.md` (ADR-5/6), refined here for the tooling reality.

## 1. Goal & Motivation

The v0.28 bitmap backend blurs when scaled up (visible on the demo's 1.4× title). SDF fixes
this: one atlas renders crisply at any size, and the distance field is the substrate the
Slice 3 effects (outline / cartoon-stroke / glow / shadow / gradient) derive from.

**Tooling reality (decided the technique):** `msdfgen` and `msdf-atlas-gen` are absent from
this environment (not in the vcpkg manifest, not installed, no system binaries). FreeType —
already vendored — ships an outline SDF renderer (`FT_RENDER_MODE_SDF`, the `sdf` module).
So Slice 2 uses **FreeType single-channel SDF**: zero new dependencies, reuses the existing
R8 `BakedFont` and `ShelfPacker` verbatim, and unblocks the effects roadmap. True multi-channel
**MSDF** (best sharp-corner fidelity, needs the `msdfgen` dependency) is a **reserved, optional
later slice** — added as another registered `FontSource` behind a compile flag if a case ever
needs it.

## 2. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Technique | FreeType single-channel SDF (`FT_RENDER_MODE_SDF`, `sdf` module); **not** MSDF this slice |
| Dependencies | None added (FreeType already present) |
| Atlas format | Unchanged **R8** `BakedFont` — SDF is single-channel |
| Spread | 8 px (FreeType `sdf` `spread` property); `pxRange` stored from it |
| Adoption | **Demo-only.** Debug HUD, `shooter_game`, `arena_game` stay on the bitmap backend (crisp already at HUD scale; zero regression surface) |
| Shader AA | `smoothstep` around the 0.5 iso-line using `fwidth(d)` (scale-adaptive); `pxRange` passed as a reserved uniform for Slice 3 |
| MSDF | Reserved / optional later slice (`msdfgen`, RGB atlas, `median(r,g,b)`) |
| Effects | Still Slice 3 (single-pass outline/glow/shadow/gradient via the style-table UBO); this slice ships crisp fill + the `pxRange` seam |

## 3. Components & changes

### 3.1 `SdfFreeTypeSource` (new)
`engine/renderer/text/SdfFreeTypeSource.hpp/.cpp`. A `FontSource` with
`backend() == FontBackend::SDF`. `bake(desc, out)`:
- Init FreeType; set pixel size; set the `sdf` module `spread` property to 8 (via
  `FT_Property_Set(lib, "sdf", "spread", &spread)`).
- For each codepoint in `desc.glyphRange`: `FT_Load_Char(face, c, FT_LOAD_DEFAULT)` to load the
  outline, then `FT_Render_Glyph(face->glyph, FT_RENDER_MODE_SDF)` to rasterize the SDF into an
  8-bit bitmap. The SDF bitmap is padded by ~`spread` px on each side vs the coverage bitmap;
  read `bitmap.width/rows` and the updated `bitmap_left`/`bitmap_top` for placement and bearings
  so the glyph still positions correctly (the extra padding shifts bearing by the spread).
- Pack each SDF bitmap into the R8 atlas via `ShelfPacker` (same as the bitmap source); fill
  `Glyph` size/bearing/advance/uv from the SDF bitmap metrics.
- `out.pxRange = spread` (distance range, in atlas px, that the [0,1] sample maps across the
  edge); populate `FaceMetrics` as in the bitmap source.
- Structurally a sibling of `BitmapFreeTypeSource`; FreeType/GL stay confined to this `.cpp`
  (not linked into `bot_arena_tests`).

Failure paths mirror `BitmapFreeTypeSource` (return false on init/face-load failure; FreeType
torn down on every path).

### 3.2 Backend: `sdf` program + backend-aware `drawTextBatch`
- **New pure virtual / override signature:**
  `drawTextBatch(FontBackend backend, uint32_t atlasTextureId, const std::vector<TextVertex>& verts, float pxRange)`
  (replaces the v0.28 `drawTextBatch(atlas, verts)`).
- `OpenGLBackend` compiles a second text program (`m_sdfTextProgram`) sharing the v0.28 text
  VAO/vertex format. Vertex shader identical (per-vertex `unpackUnorm4x8` fill). SDF fragment:
  ```glsl
  in vec2 vUV; in vec4 vFill; out vec4 FragColor;
  uniform sampler2D uAtlas;
  uniform float uPxRange;   // reserved for Slice 3 effects; AA uses fwidth here
  void main() {
    float d = texture(uAtlas, vUV).r;       // 0.5 = edge
    float w = fwidth(d);
    float a = smoothstep(0.5 - w, 0.5 + w, d);
    FragColor = vec4(vFill.rgb, vFill.a * a);
  }
  ```
- `drawTextBatch` selects the program by `backend` (`Bitmap` → bitmap program as today; `SDF` →
  sdf program, setting `uPxRange`). Same blend (`SRC_ALPHA`/`ONE_MINUS_SRC_ALPHA`), depth off,
  same VAO/upload. The SDF atlas **must sample with linear filtering** (the plan verifies the R8
  `Texture2D` already uses linear; if not, it is set for the atlas).

### 3.3 `TextRenderer::Batch` carries `pxRange`
- `struct Batch { uint32_t atlas; FontBackend backend; float pxRange; std::vector<TextVertex> verts; }`.
- `submit` sets `pxRange` from `font.pxRange` when creating a batch (constant per (backend,
  atlas), so no batch-key change). Layout/projection/vertex emission unchanged.

### 3.4 `Renderer` wiring
- `initBuiltins` registers `SdfFreeTypeSource` alongside `BitmapFreeTypeSource`
  (`m_fonts->registerSource(CreateScope<SdfFreeTypeSource>())`). The R8 atlas factory is reused
  as-is.
- `endFrame` forwards each batch's `backend` and `pxRange`:
  `m_backend->drawTextBatch(b.backend, b.atlas, b.verts, b.pxRange)`.

### 3.5 Demo (`games/text_demo`)
Add an SDF-vs-bitmap comparison: the same string rendered large (~3×) in both backends, side by
side (bitmap blurry, SDF crisp), plus the existing layered effects re-run on an SDF face (smoother
edges). Load the SDF face with `FontDesc{ backend = SDF }`. Honest label: single-channel SDF;
MSDF corner fidelity reserved.

## 4. Data flow

```
demo: fonts().load(FontDesc{family, pixelSize, backend=SDF})
   -> FontManager -> SdfFreeTypeSource.bake -> R8 SDF atlas + pxRange
   -> FontAsset{ backend=SDF, pxRange }
drawText(sdfFont, text, ScreenSpace{pos,scale}, style)
   -> TextRenderer: layout (unchanged) -> NDC -> batch{ backend=SDF, atlas, pxRange, verts }
endFrame -> backend.drawTextBatch(SDF, atlas, verts, pxRange) -> sdf program -> crisp at any scale
```
The bitmap path is byte-for-byte unchanged; SDF is a parallel branch selected by the batch's
`backend`.

## 5. Testing

- **`SdfFreeTypeSource` bake** — not unit-tested (FreeType stays out of the `bot_arena_tests`
  link, exactly as `BitmapFreeTypeSource`); validated by the demo screenshot.
- **`TextRenderer`** — extend the batch test to assert a submitted font's `pxRange` and `backend`
  are recorded on the resulting `Batch` (CPU, stub font with a non-zero `pxRange`). All existing
  text tests stay green.
- **Acceptance** — inspected screenshot: SDF text crisp at ~3× where bitmap blurs; bitmap
  HUD/shooter/arena render identically to v0.28.

## 6. Risks & mitigations

- **SDF bearing/padding drift.** FreeType's SDF bitmap is padded by the spread, shifting
  `bitmap_left/top`. Mitigation: derive size/bearing from the SDF bitmap's own metrics (not the
  coverage bitmap), and verify glyph positioning in the demo screenshot.
- **Nearest-filtered atlas.** SDF needs bilinear sampling or it looks blocky. Mitigation: the plan
  confirms/sets linear filtering on the R8 atlas texture.
- **FreeType version lacks the `sdf` module.** Mitigation: the vendored FreeType is modern
  (2.11+); the plan checks `FT_RENDER_MODE_SDF` is available and, if a bake fails, the source
  returns false and `FontManager::load` returns null (demo degrades, no crash).
- **`drawTextBatch` signature change** ripples to `RenderBackend`/`OpenGLBackend`/`Renderer`.
  Mitigation: single small, mechanical change; `OpenGLBackend` is the only subclass.

## 7. Open items (deferred, not blocking)

- Exact `pxRange`→outline-width mapping for effects (decided in Slice 3).
- MSDF via `msdfgen`: RGB atlas, `BakedFont` channel count, `median(r,g,b)` shader (reserved
  optional slice).
- Whether the HUD/games later opt into SDF (trivial `FontDesc` change; deferred).

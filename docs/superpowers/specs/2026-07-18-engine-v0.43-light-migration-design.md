# Engine v0.43 — Finish the LightComponent migration (Scene-based games)

## Problem

v0.42 shipped `LightComponent` + the additive `Scene::render` collection pass,
but migrated only scene_demo (directional) and arena (point) as proofs. Three
more games are **already on `Scene`** yet still set their lights by hand in
`onRender`:

- **shooter** — one static point key light.
- **models** — one static point key light.
- **controller_demo** — one static directional light (+ empty point lights).

This slice migrates those three so every Scene-based game is fully
scene-driven, and hardens `collectLights` against the zero-vector directional
NaN noted as v0.42 Minor #1.

### Why only three games

`LightComponent` is collected by `Scene::render`; a game that never calls
`m_scene.render(...)` cannot use it. Six remaining light-setting games —
particles, camera_demo, billboard_demo, normalmap_demo, parallax_light_demo,
csm_demo — are **not on `Scene`** (they render manually). Migrating their
lighting requires first migrating them onto `Scene`, a separate and larger
effort (the reserved "migrate remaining games onto Scene" backlog item). They
are explicitly out of scope here and keep their manual `onRender` light calls,
which the additive wiring leaves untouched.

## Design

### 1. Zero-vector directional guard in `collectLights`

`collectLights` currently does `glm::normalize(t.translation)` unconditionally
for a directional light. A directional entity whose translation is the default
`{0,0,0}` (a misconfiguration) yields `normalize({0,0,0})` = NaN/Inf, which
would silently poison `setLightDirection` (and thus CSM shadows + IBL). Guard
the directional branch:

```cpp
} else if (!out.hasDirectional &&
           glm::dot(t.translation, t.translation) > kMinLen2) {
  out.hasDirectional = true;
  out.directionalDir = glm::normalize(t.translation);
}
```

- `glm::dot(v, v)` is squared length using **core GLM only** — `glm::length2`
  lives in `glm/gtx/norm.hpp`, and this codebase forbids `gtx` (the
  `GLM_ENABLE_EXPERIMENTAL` trap). `glm::dot` is in `<glm/glm.hpp>`, already
  included.
- `kMinLen2` is a small `constexpr float` (`1e-12f`) — it filters only a true
  zero / denormal translation, never a real light direction (the smallest real
  one in use, `{0.5,0.7,0.35}`, has squared length ≈ 0.82).
- A zero-length directional is **ignored**: it does not set `hasDirectional`,
  so it does not consume the "first directional wins" slot. A later valid
  directional in the same scene still wins; a scene whose only directional is
  degenerate reports `hasDirectional=false`, and `Scene::render` leaves the
  renderer's directional at its default (additive contract preserved).

New unit cases in `tests/test_light_collection.cpp`:

- directional with zero translation → `hasDirectional` false, `points` empty;
- a zero-translation directional followed by a valid directional → the valid
  one wins (`directionalDir == normalize(valid.translation)`).

The existing five cases are unchanged.

### 2. Migrate the three Scene-based games

Same mechanical pattern as scene_demo/arena: create the light `SceneObject` once
in `onAttach` (a `LightComponent` needs no `Renderer`, so — unlike
`ModelComponent` — even shooter's pre-resource warm-up can attach it directly at
`onAttach`, with no lazy-attach path), set its `TransformComponent.translation`,
`addComponent<LightComponent>`, and delete the manual light calls from
`onRender`. Each is screenshot-gated against its pre-migration baseline at
**AE = 0**, because `collectLights` reproduces the identical `PointLight` /
directional vector.

| Game | Old `onRender` light | New light entity |
|---|---|---|
| **shooter** | point: `positionRadius=(0,8,4,40)`, `color=(1,0.97,0.9,3.0)` | `translation={0,8,4}`, `LightComponent{Point, {1,0.97,0.9}, 3.0f, 40.0f}` |
| **models** | point: `positionRadius=(2,3,2,15)`, `color=(1,0.97,0.9,2.5)` | `translation={2,3,2}`, `LightComponent{Point, {1,0.97,0.9}, 2.5f, 15.0f}` |
| **controller_demo** | directional `normalize(0.5,0.7,0.35)` + `setPointLights({})` | `translation={0.5,0.7,0.35}`, `LightComponent{Directional, ...}` |

For shooter and models, delete the `std::vector<engine::PointLight>` build and
the `renderer.setPointLights(...)` call; for controller_demo, delete both
`renderer.setLightDirection(...)` and `renderer.setPointLights({})`. In each
file, if the `#include "engine/renderer/PointLight.hpp"` is left unused after
the deletion, remove it (grep the file to confirm no `engine::PointLight`
reference remains).

### 3. Wiring stays additive

`Scene::render` is unchanged — both setters stay guarded
(`if (!cl.points.empty())`, `if (cl.hasDirectional)`). The additive→authoritative
flip's precondition ("every game on `Scene`") is still unmet while the six
off-Scene demos exist, so the flip is deferred; staying additive keeps one
uniform rule and leaves the six manual games working. After this slice, the
flip (when it eventually happens) is just deleting the two guards.

## Testing

- `tests/test_light_collection.cpp` gains the two zero-vector guard cases
  (Catch2, GL-free) — total 7 cases.
- shooter, models, controller_demo each screenshot-verified with
  `BOTARENA_SCREENSHOT=<path> ./build/<game>` against a pre-migration baseline;
  target AE = 0 (AA/rounding noise only).
- shooter also runs its gameplay unit tests (`test_steering`, `test_wall_bounce`,
  `test_agent_collision`, `test_ship_controls`) to confirm the lighting change
  didn't disturb simulation.

## Non-goals / reserved for later slices

- **The six off-Scene games** (particles, camera_demo, billboard_demo,
  normalmap_demo, parallax_light_demo, csm_demo) — blocked on a prior
  Scene migration; keep their manual light calls.
- **The additive→authoritative flip** — deferred until all games are on
  `Scene`.
- **Multiple directional lights**, **per-submesh material overrides**,
  **sort/cull/instancing**, and the **`addComponent<T>` empty-tag fix** remain
  reserved.

## Decisions table

| Decision | Choice | Why |
|---|---|---|
| Scope | shooter + models + controller_demo only | the only remaining games on `Scene`; `LightComponent` needs `Scene::render` |
| Zero-vector guard | `glm::dot(v,v) > kMinLen2` (`1e-12f`), core GLM | fixes v0.42 NaN footgun without `gtx`; degenerate directional ignored, not counted |
| Attach timing | light entity created in `onAttach` (no lazy attach) | `LightComponent` needs no `Renderer`, unlike `ModelComponent` |
| Wiring | stays additive | flip precondition (all games on `Scene`) unmet; YAGNI |
| Verification | screenshot AE=0 per game + guard unit tests | mirrors v0.42's proof method |

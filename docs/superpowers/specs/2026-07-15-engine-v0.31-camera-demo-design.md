# Engine v0.31 — Camera Views Demo — Design Spec

**Date:** 2026-07-15
**Status:** Approved for planning
**Scope:** A new example game (`camera_demo`) that renders a shared 3D scene viewable through four camera projections/controllers and overlays the SDF text HUD + effects, proving the screen-space text system renders correctly over every camera view. It is an integration/demo game in the style of the existing example games — no new engine features.
**Builds on:** v0.30 SDF text effects (branch `feat/engine-v0.30-sdf-effects`), plus the existing camera controllers and mesh rendering.

## 1. Goal & Motivation

The text system (v0.28–v0.30) is screen-space only; world-space 3D text is a later slice. This
example verifies that the screen-space SDF HUD (with the v0.30 outline/glow/shadow effects)
renders correctly and legibly **regardless of the 3D camera projection**, while also serving as
a compact tour of the engine's camera views. It reuses the existing mesh-rendering, camera, and
text APIs — following the pattern of `games/arena`, `games/shooter`, etc. — and adds no engine
code.

## 2. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Deliverable | New example game `camera_demo` (`camera_demo_game` target), like the other `games/` examples |
| Namespace | `camerademo` |
| Camera views | 4: **Orbit** (auto-rotating), **Fly/first-person**, **Top-down orthographic**, **Front (fixed perspective)** |
| Switching | Cycle key (Tab) + number keys (1–4) in `onUpdate`; **`BOTARENA_VIEW=0..3` env** sets the initial view for headless screenshots |
| Scene | Ground quad + a small grid/ring of cubes with varied PBR materials + a few colored point lights (reused mesh rendering) |
| HUD | SDF font + v0.30 effects: title (outline), active view name large (glow), view list w/ active highlighted, live camera pos/target, controls hint (shadow) |
| Engine changes | **None** — reuses `CameraController`/`OrbitCameraController`/`FlyCameraController`, `PerspectiveCamera`/`OrthographicCamera`, `MeshRenderer`, `Renderer::setCamera`, and the text API |
| Testing | `BOTARENA_VIEW` × `BOTARENA_SCREENSHOT` → capture + visually inspect all four views. No unit tests (matches the other example games) |

## 3. Components

### 3.1 `CameraDemoGame` (`engine::Layer`)
- **State:** `OrbitCameraController m_orbit;` `FlyCameraController m_fly;` `PerspectiveCamera m_front;`
  `OrthographicCamera m_top;` an active-view index `int m_view = 0;` (0..3), `float m_time = 0;`,
  scene material handles, a `bool m_resourcesReady`, and `engine::FontHandle m_font` (SDF).
- **`onAttach`:** read `BOTARENA_VIEW` env → `m_view` (clamped 0..3).
- **`onUpdate(dt)`:** accumulate `m_time`; read input — `Key::Tab` cycles `m_view = (m_view+1)%4`,
  `Key::Num1..Num4` select directly; update the active driver (`m_orbit.update`/`m_fly.update`;
  the raw cameras need no per-frame update besides re-aiming). Orbit auto-rotates via
  `setOrbit(baseYaw + m_time*rotSpeed, pitch, distance)`.
- **`onRender(renderer, w, h)`:** lazy-init materials (first frame) and the SDF font; compute
  `aspect`; configure + fetch the active camera (see 3.2); `renderer.setCamera(cam)`; set point
  lights; submit the scene meshes via `MeshRenderer`; draw the HUD (3.3).

### 3.2 The four views — `const Camera& activeCamera(float aspect)`
Configures the active camera's projection for `aspect` and returns it:
- **Orbit (0):** `m_orbit.setTarget(center); m_orbit.setOrbit(yaw, pitch, distance); m_orbit.resize(aspect);`
  return `m_orbit.camera()`.
- **Fly (1):** `m_fly.resize(aspect);` return `m_fly.camera()` (pose set once in `onAttach`;
  `m_fly.update` in `onUpdate` handles WASD/right-drag).
- **Top-down ortho (2):** `m_top.setBounds(-halfH*aspect, halfH*aspect, -halfH, halfH, -100, 100);`
  `m_top.lookAt({0, 14, 0.001f}, {0, 0, 0});` return `m_top`. The `0.001f` z-offset avoids the
  degenerate straight-down `lookAt` (view direction parallel to the hard-coded up vector →
  NaN view matrix).
- **Front fixed (3):** `m_front.setPerspective(55, aspect, 0.1f, 100.0f);`
  `m_front.lookAt({0, 3.5f, 14.0f}, {0, 1.0f, 0.0f});` return `m_front`.

All four return a `const Camera&` that `Renderer::setCamera(const Camera&)` consumes (it reads
`view()`/`projection()`), so both controller-owned and raw cameras work uniformly.

### 3.3 HUD (SDF font + v0.30 effects)
Loaded once as an SDF face (`FontDesc{ ..., backend = SDF }`). Screen-space, laid clear of the
top-left debug overlay:
- **Title** — "Camera Views" with an outline (`outlineColor`/`outlineWidthPx`).
- **Active view name** large — e.g. `ORBIT` / `FLY (FPS)` / `TOP-DOWN (ortho)` / `FRONT (fixed)`
  — with a glow (`glowColor`/`glowSizePx`).
- **View list** — the four names stacked; the active one brightened, others dimmed.
- **Camera readout** — active camera position and (where meaningful) target, formatted to 1 dp.
- **Controls hint** — "Tab / 1-4: switch view · WASD + right-drag: fly" with a drop-shadow
  (`shadowColor`/`shadowOffsetPx`/`shadowSoftnessPx`).

This exercises fill + outline + glow + shadow over each camera projection in one place.

## 4. Data flow

```
onUpdate: input -> m_view (Tab/1-4); m_time += dt; active driver .update(dt)
onRender:
  aspect = w/h
  const Camera& cam = activeCamera(aspect)   // configures projection + aim
  renderer.setCamera(cam)
  renderer.setPointLights(...)
  MeshRenderer submits ground + cubes
  HUD: renderer.drawText(sdfFont, ..., TextStyle{effects})   // screen-space, over any view
```

## 5. Testing

- **Headless capture per view:** `BOTARENA_VIEW=<0..3> BOTARENA_SCREENSHOT=<path> ./build/camera_demo_game`
  renders one frame in that view and exits. The controller captures all four and visually
  confirms: the scene renders correctly under each projection (orbit/fly perspective, top-down
  orthographic, fixed front) and the SDF HUD + effects are legible over each.
- **Build:** `camera_demo_game` and the full build link clean; existing suite stays green (no
  engine changes).
- No unit tests (consistent with the other example games).

## 6. Risks & mitigations

- **Degenerate top-down `lookAt`.** A perfectly straight-down view direction is parallel to the
  ortho camera's hard-coded up vector → NaN. Mitigated by the `0.001f` z-offset in the eye
  position; verified in the top-down screenshot.
- **`BOTARENA_VIEW` parsing.** Clamp to 0..3; default 0 when unset/invalid so the app never
  starts in a bad state.
- **Input key availability.** The switch keys must exist in the engine's `Key` enum (`Tab`,
  `Num1..Num4`). The plan verifies the exact enum names before wiring; if a key is absent, fall
  back to the ones that exist (at minimum a single cycle key).
- **HUD/debug overlay overlap.** Lay the HUD clear of the top-left engine debug overlay (same as
  `text_demo`).

## 7. Open items (deferred, not blocking)

- World-space/billboard 3D labels anchored to scene objects — needs the reserved world-space text
  slice; this demo stays screen-space.
- Smooth animated transitions between views (cut is fine for a test/example).

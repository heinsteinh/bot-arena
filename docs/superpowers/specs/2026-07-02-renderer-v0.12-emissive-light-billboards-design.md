# Renderer v0.12 — Emissive Point-Light Billboards — Design Spec

**Date:** 2026-07-02
**Status:** Approved for planning
**Scope:** Engine v0.12 — draw each point light as a bright camera-facing emissive
billboard in the HDR scene after lighting, so the v0.11 bloom pass turns them into
glowing orbs.
**Builds on:** v0.11 SSAO + bloom (merged to `main`).

## 1. Goal & Motivation

The ~16 animated point lights illuminate the scene but are not drawn, so v0.11's
bloom had no compact emitters and needed a low threshold to show any glow. v0.12
draws each light as an additive glowing disc at its position (colour × intensity,
HDR) in the HDR scene before bloom. The lights become visible glowing orbs, bloom
gains real emitters, and its threshold can go back up for a targeted glow.

## 2. Roadmap context (this spec is v0.12 only)

| Milestone | Adds |
| --- | --- |
| v0.1–v0.11 (done) | …, deferred G-buffer, PBR, IBL, SSAO + bloom. |
| **v0.12 (this spec)** | Instanced emissive point-light billboards in the HDR scene; bloom threshold raised. |
| Later | Depth-occluded / soft-particle billboards, textured light sprites, HDR flares/streaks, light culling. |

## 3. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Billboard | Camera-facing quad per light, instanced from the binding-2 `PointLights` UBO; radial soft-disc falloff; **additive** blend |
| Colour | `u_points[i].color.rgb * u_points[i].color.a` (intensity) × falloff — HDR, well above 1 |
| Size | `0.25` world units |
| Placement in frame | HDR scene FBO, **after** the lighting pass, **before** bloom |
| Depth | **No depth test** (lights float at `y=1.5`, above the swarm/walls); occlusion is a follow-up |
| Bloom threshold | Raised from `0.45` to `1.0` (real emitters now drive bloom) |
| Camera axes | Right/up extracted from the view matrix in the Camera UBO (binding 0) |
| DoD | ~16 coloured glowing orbs on the light ring above the swarm, each haloed by bloom |

## 4. Architecture & data flow

```
Renderer::endFrame
  shadow → geometry → SSAO → lighting (→ HDR sceneFBO + skybox)
  // --- emissive light billboards (new) ---
  (sceneFBO still bound) drawLightBillboards(pointLightCount)   // additive, into HDR
  // --- bloom (threshold now 1.0) ---
  bloom extract/blur → composite(scene + bloom)
```

The billboards write into the same HDR `sceneFBO` the lighting pass just filled, so
they are part of the HDR image the bloom bright-pass reads.

## 5. Emissive billboard shader (backend-owned, inline)

- **Vertex** (instanced, `count` instances over the unit quad `a_position` in
  `[0,1]²`):
  - reads `u_points[gl_InstanceID]` from the `PointLights` UBO (binding 2:
    `{ int u_pointCount; PointLight u_points[32]; }`, `PointLight { vec4
    positionRadius; vec4 color; }`);
  - camera axes from the Camera UBO (binding 0): `right = vec3(u_view[0][0],
    u_view[1][0], u_view[2][0])`, `up = vec3(u_view[0][1], u_view[1][1],
    u_view[2][1])`;
  - `local = a_position * 2 - 1` (quad in `[-1,1]²`); `world =
    center + (local.x*right + local.y*up) * u_size`;
  - `gl_Position = u_viewProjection * vec4(world, 1)`; passes `local` and the
    light colour to the fragment stage.
- **Fragment:** `falloff = smoothstep(1.0, 0.0, length(local))`; `fragColor =
  vec4(color.rgb * color.a * falloff, 1.0)` (additive blend makes it glow; alpha
  unused under additive).

`u_size = 0.25` is a shader uniform set in `drawLightBillboards`.

## 6. Backend

`RenderBackend::drawLightBillboards(int count)`:

- `glEnable(GL_BLEND); glBlendFunc(GL_ONE, GL_ONE)` — additive (the radial falloff
  is baked into the output colour);
- `glDisable(GL_DEPTH_TEST)`;
- bind the emissive program, set `u_size`;
- `glBindVertexArray(m_quadVao); glDrawArraysInstanced(GL_TRIANGLE_STRIP, 0, 4,
  count);`
- restore: `glDisable(GL_BLEND)`.

The emissive program is created in the constructor and freed in the destructor. It
reads the already-bound Camera UBO (binding 0) and `PointLights` UBO (binding 2);
no new buffers.

## 7. Renderer

- `Renderer` remembers `m_pointLightCount` (set in `setPointLights` from the vector
  size, clamped to 32 to match the UBO).
- `endFrame`: after `lightingPass(...)` (the scene FBO is still bound from its
  `beginPass`), call `m_backend->drawLightBillboards(m_pointLightCount)` before the
  bloom sub-sequence.
- The bloom bright-pass threshold rises to `1.0` (in the backend's
  `bloomExtract`).
- `BotArenaGame` is unchanged.

## 8. Testing

- **Unit:** none new — a shader + a draw call; the billboard-corner/falloff math is
  in-shader and CPU duplication would break DRY (consistent with prior GPU-only
  pieces). The existing 36 Catch2 cases stay green.
- **Behavioral:** `BOTARENA_SCREENSHOT` shows ~16 coloured glowing orbs floating on
  the ring above the swarm, each with a bloom halo; the swarm/ground lighting is
  otherwise as v0.11 (minus the general haze, since the threshold rose).

## 9. Out of scope (later milestones)

Depth-tested billboards (foreground geometry occluding orbs), soft-particle edge
fade against geometry, textured light sprites, HDR flares/anamorphic streaks, and
light culling. This milestone is the minimal emissive-sprite pass.

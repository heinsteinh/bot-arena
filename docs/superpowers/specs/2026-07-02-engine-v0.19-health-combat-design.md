# Engine v0.19 — Health & Combat Loop — Design Spec

**Date:** 2026-07-02
**Status:** Approved for planning
**Scope:** Contact-based combat for the arena — Health on player and bots, mutual
contact damage, bot death/recycle and player respawn, bot regen, low-health flee, and
a small on-screen HP/Kills readout.
**Builds on:** v0.16 steering (`seek`/`flee`) and v0.15 collision, on `main`. Fourth
gameplay milestone.

## 1. Goal & Motivation

The arena has bots that chase the player but nothing happens on contact. v0.19 adds a
combat loop: bots damage the player on touch and the player damages them back (player
stronger, swarm lethal); dying bots recycle, the player respawns; wounded bots flee to
heal and re-engage — turning the v0.16 `flee` primitive into real behaviour.

## 2. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Combat | Contact damage, no attack input. Overlapping player↔bot deal mutual DPS each fixed step. |
| Params | Player `100` HP / `40` DPS; bot `30` HP / `8` DPS; bot regen `6`/s (only when not touching); flee under `35%` HP |
| Bot death | Recycle: full HP + teleport to a random arena-edge point; `kills` counter increments |
| Player death | Respawn at center with full HP; `deaths` counter increments |
| Flee | A bot at/under `35%` HP uses `flee` instead of `seek` (retreat, heal, return) |
| Tested core | `adjustHealth` + `shouldFlee` in `engine/gameplay/Combat.hpp` (pure, header-only) |
| Readout | `ArenaGame` draws `HP: n / max` and `Kills: n` bottom-left via the v0.17 text renderer |
| DoD | After the warm-up, player HP is reduced and `Kills > 0`; the readout shows it |

## 3. Component & constants

Add to `games/arena/Components.hpp`:

```cpp
struct Health {
  float current = 0.0f;
  float max = 0.0f;
};
```

`spawnEntities`: player gets `Health{100, 100}`; each bot gets `Health{30, 30}`.

`ArenaGame` constants: `kPlayerMaxHealth = 100.0f`, `kBotMaxHealth = 30.0f`,
`kPlayerDps = 40.0f`, `kBotDps = 8.0f`, `kBotRegen = 6.0f`, `kFleeFraction = 0.35f`,
`kArenaEdge = 4.5f`. New members: `int m_kills = 0`, `int m_deaths = 0`,
`Ref<Font> m_font`.

## 4. The tested core

`engine/gameplay/Combat.hpp` (header-only, EnTT/GL-free):

```cpp
// Clamp current+delta to [0, max]. delta<0 damages, delta>0 heals.
inline float adjustHealth(float current, float delta, float max) {
  const float v = current + delta;
  if (v < 0.0f) return 0.0f;
  if (v > max) return max;
  return v;
}

// True when the agent is alive and at/under the flee fraction of max health.
inline bool shouldFlee(float current, float max, float fleeFraction) {
  return current > 0.0f && current <= max * fleeFraction;
}
```

## 5. System integration (`ArenaGame::stepSim`)

Order becomes:

1. **Input → player velocity** (unchanged).
2. **Steering (health-aware)** — read the player position; for each bot,
   `shouldFlee(botHealth) ? flee(...) : seek(...)`, then accelerate + clamp (v0.16).
3. **Integrate** (unchanged).
4. **Agent collision** (unchanged, v0.15).
5. **Wall bounce** (unchanged, v0.14).
6. **Combat** — for each bot, XZ distance to the player: if `< botScale +
   playerScale`, apply `adjustHealth(player, -kBotDps*dt)` and `adjustHealth(bot,
   -kPlayerDps*dt)`; else `adjustHealth(bot, +kBotRegen*dt)`.
7. **Death / respawn** — bot `current <= 0` → recycle to a random edge point
   (`angle` on a radius-`kArenaEdge` ring), reset to full HP, `m_kills++`; player
   `current <= 0` → move to center, reset to full HP, `m_deaths++`.

The deterministic 120-step warm-up now runs combat, so the initial rendered frame
already reflects damage and kills.

## 6. On-screen readout

`ArenaGame::onAttach` loads `m_font = Font::Load(BOTARENA_ASSET_DIR
"/fonts/DejaVuSans.ttf", 32)`. `onRender` queries the player's `Health` and draws two
lines bottom-left (clear of the F1 debug HUD): `HP: <cur> / <max>` and `Kills:
<m_kills>`, scale `0.7`, white.

## 7. Testing

- **Unit (Catch2, no GL/EnTT):** `adjustHealth` (damage within range; over-damage
  clamps to 0; heal caps at max; normal heal) and `shouldFlee` (full → false; at/under
  fraction → true; dead → false).
- **Behavioral:** `arena_game` — after the warm-up, a startup log reports player HP and
  kills (both showing combat ran); the screenshot shows the swarm on the player with a
  reduced `HP` readout and `Kills > 0`.

## 8. Out of scope (later)

Attack input/abilities, weapons/projectiles, damage cooldowns/i-frames, XP/leveling,
per-entity health bars, factions/teams, and win/lose conditions (the next milestone,
arena game rules).

# Engine v0.23 — Model Material Colors — Design Spec

**Date:** 2026-07-02
**Status:** Approved for planning
**Scope:** Read each sub-mesh's diffuse color (`Kd`) from the `.mtl` via Assimp and
render multi-material models with their real per-part colors. No UV / shader / texture
changes (textures are the next milestone).
**Builds on:** v0.22 Assimp loading, on `main`. First half of the material split
(colors now, textures next).

## 1. Goal & Motivation

`loadModel` currently merges every sub-mesh into one grey mesh, discarding the `.mtl`
materials. v0.23 keeps sub-meshes separate and gives each the diffuse color from its
Assimp material, so a model like `monitor.obj` (red body, green screen, …) shows its
real colors. This is the "even color materials" path; textured albedo maps come in
v0.24.

## 2. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Split | `Model` becomes a list of sub-meshes, each with its own `MeshHandle` + `MaterialHandle` (no merge) |
| Color | Per sub-mesh: `AI_MATKEY_COLOR_DIFFUSE` → `baseColor` (fallback `0.8` grey if absent); `metallic 0`, `roughness 0.55` |
| Signature | `loadModel(path, registry, shader)` — the shader handle is needed to register materials |
| Render | The viewer submits every sub-mesh with its material under the one model transform |
| Demo | Commit `monitor.obj`/`monitor.mtl` (multi-color) and default the viewer to it |
| No change | Vertex layout (position+normal), `mesh.glsl`, textures — deferred to v0.24 |
| DoD | `models_game` screenshot shows a multi-color model (Monitor) with distinct per-part colors |

## 3. Loader changes (`engine/assets/ModelLoader.{hpp,cpp}`)

```cpp
struct Submesh {
  MeshHandle mesh = 0;
  MaterialHandle material = 0;
};

struct Model {
  std::vector<Submesh> submeshes;
  AABB bounds{};
  bool valid = false;
};

Model loadModel(const std::string& path, ResourceRegistry& registry,
                ShaderHandle shader);
```

For each `aiMesh`: build a position+normal `VertexArray` → `registerMesh`; read the
diffuse color from `scene->mMaterials[mesh->mMaterialIndex]`
(`aiGetMaterialColor(..., AI_MATKEY_COLOR_DIFFUSE, ...)`, fallback grey) →
`registerMaterial({color, 0.0f, 0.55f, shader})`; push `{mesh, material}`. Accumulate
all positions across sub-meshes for `computeBounds`. Failure / no geometry →
`{valid=false}`.

## 4. Viewer changes (`games/models/`)

`ModelsGame::onRender` loads each curated model with
`loadModel(assetPath(path), renderer.registry(), renderer.meshShader())`, and renders
the selected model by submitting **every** sub-mesh with its own material under
`fitToUnitTransform(bounds) * rotate(angle)`. The per-model solid material (`m_modelMat`)
is removed (materials now come from the model); the ground keeps its material.
`monitor.obj` is added to the curated list and is the default selection.

## 5. Testing

Integration/asset milestone — verified by screenshot; no new pure unit (the
`MeshBounds` tests and the v0.22 loader path stand). `computeBounds` is reused for the
merged bounds.

- **Behavioral:** `models_game` logs `Loaded model .../monitor.obj (...)`; the
  screenshot shows the Monitor with distinct per-part colors (a red body and green
  screen, not uniform grey). Suzanne and the other single-material models still render.
  `bot_arena`/`arena_game`/`particles_game` unchanged.

## 6. Out of scope (this milestone)

Albedo/`map_Kd` textures, the UV vertex attribute, RGBA `Texture2D`, and shader
sampling — all in **v0.24 (textured materials)**. Also: normal/metallic/roughness maps,
specular, per-material metallic/roughness from `Ns`.

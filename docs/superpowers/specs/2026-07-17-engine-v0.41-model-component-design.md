# Engine v0.41 — ModelComponent (multi-submesh scene rendering) — Design Spec

**Date:** 2026-07-17
**Status:** Approved for planning
**Scope:** Add a `ModelComponent` so a single scene entity draws a whole multi-submesh `Model` through `Scene::render`, back it with model storage in `ResourceRegistry` (a `ModelHandle`), migrate `models_game` to it as an isolated proof, and retire `shooter`'s render-proxy workaround (the v0.40 debt) by putting a `ModelComponent` directly on each ship/enemy/bullet.
**Builds on:** v0.38 Scene/SceneObject/TransformComponent/CameraComponent; v0.39 quaternion TransformComponent + controller systems; v0.40 MeshComponent + `Scene::render` (`SceneRender.cpp`, engine-lib-only).

## 1. Goal & Motivation

v0.40's `MeshComponent` holds exactly one `{mesh, material}`, but `loadModel` returns a **multi-submesh** `Model` (Viper = 3 submeshes, eliteship = 7). Shooter bridged the gap with render-only proxy `SceneObject`s — one per submesh — synced every frame (`m_visualParts` map, `attachVisual`/`syncVisual`/`attachMissingVisuals`/`syncAllVisuals`, and a `destroyActor` that cleans proxies). It is sound but heavy and duplicated. `ModelComponent` is the proper fix: one component on one entity draws all the model's submeshes at the entity's transform, and the proxy machinery is deleted.

## 2. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Model storage | `ResourceRegistry` gains `ModelHandle registerModel(const Model&)` + `const Model& model(ModelHandle) const` (a `std::vector<Model>` store), matching the existing `registerMesh`/`registerMaterial` pattern. `using ModelHandle = uint16_t;` in `RenderCommand.hpp`. |
| Header cycle | Extract `Submesh` + `Model` into a data-only `engine/assets/Model.hpp` (includes `MeshBounds.hpp` for `AABB`); `ModelLoader.hpp` includes it and keeps `loadModel`. Breaks the `ResourceRegistry ↔ ModelLoader` include cycle. |
| `ModelComponent` | Data-only `{ ModelHandle model = 0; bool normalized = true; MaterialHandle materialOverride = 0; glm::quat rotationOffset{1,0,0,0}; }` in its own header (`engine/scene/ModelComponent.hpp`), like `MeshComponent`. |
| `rotationOffset` | **Render-only** facing correction (identity by default). `Scene::render` draws with `t.rotation * rotationOffset` — the gameplay `TransformComponent.rotation` stays pure heading. Fixes models that import facing the wrong way (shooter ships face opposite their heading → `rotationOffset = angleAxis(π, +Y)`). Gameplay reads `TransformComponent.rotation` back for aiming, so the flip **must not** live there. |
| `normalized` | When true, `Scene::render` composes `fitToUnitTransform(model.bounds)` (existing helper, `MeshBounds.hpp`) after the entity transform — same fit-to-unit-cube the games already apply. |
| `materialOverride` | `0` = use each submesh's baked material; non-zero = tint **all** submeshes with that material (shooter bullet team-tint). `0`-as-"none" is a pragmatic sentinel — overriding a model submesh to material 0 (a game's first-registered material) is nonsensical; documented. |
| `Scene::render` | Adds a **second** iteration over `<TransformComponent, ModelComponent>` (in `SceneRender.cpp`), after the existing `<TransformComponent, MeshComponent>` loop. Looks up the model, builds `m = t.localTransform()` (×`fitToUnitTransform` if normalized), submits each submesh with the resolved material. |
| Proof (isolated) | `models_game` migrated: register the loaded model → `ModelHandle`, one `SceneObject` with `ModelComponent`, render via `Scene::render`. Keeps its ImGui viewer + camera. Screenshot matches baseline. |
| Debt cleanup (real game) | `shooter` proxy machinery deleted; ships/enemies get `ModelComponent{model}`, bullets get `ModelComponent{bulletModel, materialOverride = tintMat}`. The `kShipYaw` flip folds into the entity `TransformComponent.rotation`. Screenshot matches v0.40 shooter. |
| Testing | `registerModel`/`model` round-trip and `fitToUnitTransform` are pure → **unit-tested** (GL-free `bot_arena_tests`). `Scene::render`'s model path stays GL-bound → screenshot-verified via models_game + shooter. |
| Untouched | `MeshComponent` stays (arena, scene_demo, controller_demo still use it; single-submesh entities). |
| Reserved | `LightComponent`; per-submesh material overrides; sort/cull + instancing in `Scene::render`; the `addComponent<T>` empty-tag fix; migrating remaining games. |

## 3. Components & changes

### 3.1 `engine/assets/Model.hpp` (new, data-only — extracted from `ModelLoader.hpp`)
```cpp
#pragma once
#include "engine/assets/MeshBounds.hpp"        // AABB
#include "engine/renderer/RenderCommand.hpp"   // MeshHandle, MaterialHandle
#include <vector>
namespace engine {
struct Submesh { MeshHandle mesh = 0; MaterialHandle material = 0; };
struct Model   { std::vector<Submesh> submeshes; AABB bounds{}; bool valid = false; };
}
```
`ModelLoader.hpp` `#include`s this (drops the inline `Submesh`/`Model` definitions) and keeps `Model loadModel(const std::string&, ResourceRegistry&, ...)`.

### 3.2 `ModelHandle` (`engine/renderer/RenderCommand.hpp`)
Add `using ModelHandle = uint16_t;` beside the existing `MeshHandle`/`MaterialHandle`.

### 3.3 `ResourceRegistry` model store (`ResourceRegistry.hpp` + `.cpp`)
```cpp
// ResourceRegistry.hpp  (include "engine/assets/Model.hpp")
ModelHandle registerModel(const Model& model);   // stores a copy, returns index
const Model& model(ModelHandle handle) const;    // lookup
// private: std::vector<Model> m_models;
```
`registerModel` pushes and returns `static_cast<ModelHandle>(index)`; `model` returns `m_models[handle]`. No include cycle: `Model.hpp` is data-only.

### 3.4 `ModelComponent` (`engine/scene/ModelComponent.hpp`, new)
```cpp
#pragma once
#include <glm/gtc/quaternion.hpp>              // glm::quat
#include "engine/renderer/RenderCommand.hpp"   // ModelHandle, MaterialHandle
namespace engine {
struct ModelComponent {
  ModelHandle    model = 0;
  bool           normalized = true;        // fit bounds into a unit cube (fitToUnitTransform)
  MaterialHandle materialOverride = 0;     // 0 = baked submesh materials; else tint all
  glm::quat      rotationOffset{1.0f, 0.0f, 0.0f, 0.0f};  // render-only facing fix
};
}
```

### 3.5 `Scene::render` model path (`engine/scene/SceneRender.cpp`)
Append after the existing mesh loop (same `MeshRenderer meshes`):
```cpp
auto models = m_registry.view<TransformComponent, ModelComponent>();
for (const entt::entity e : models) {
  const TransformComponent& t = models.get<TransformComponent>(e);
  const ModelComponent& mc = models.get<ModelComponent>(e);
  const Model& model = renderer.registry().model(mc.model);
  const glm::quat rot = t.rotation * mc.rotationOffset;   // render-only facing
  glm::mat4 m = glm::translate(glm::mat4(1.0f), t.translation) *
                glm::mat4_cast(rot) *
                glm::scale(glm::mat4(1.0f), t.scale);
  if (mc.normalized) m = m * fitToUnitTransform(model.bounds);
  for (const Submesh& sm : model.submeshes) {
    const MaterialHandle mat = mc.materialOverride != 0 ? mc.materialOverride : sm.material;
    meshes.submit(sm.mesh, mat, m);
  }
}
```
`SceneRender.cpp` gains `#include "engine/assets/Model.hpp"`, `"engine/assets/MeshBounds.hpp"`, `"engine/scene/ModelComponent.hpp"`. Stays engine-lib-only (GL via `Renderer.hpp`) — the GL-free tests target is unaffected.

### 3.6 `models_game` migration (`games/models/`)
`onLoad`: `ModelHandle h = renderer.registry().registerModel(loadModel(...))`; create a `SceneObject` with `TransformComponent` + `ModelComponent{h}` (ground stays a `MeshComponent`). `onRender`: replace the manual `for (Submesh …) meshes.submit(… m*fitToUnitTransform …)` loop with `m_scene.render(renderer, aspect)` (after lights). The ImGui viewer + camera keep working; when the viewer cycles models, swap the entity's `ModelComponent.model` to the newly registered handle. Screenshot matches the pre-migration model viewer.

### 3.7 `shooter` proxy retirement (`games/shooter/`)
Delete `m_visualParts`, `attachVisual`, `syncVisual`, `attachMissingVisuals`, `syncAllVisuals`, and `destroyActor`'s proxy cleanup (its actor-destroy role folds back to plain `destroy`). Register each ship/enemy/bullet model once → `ModelHandle`. On spawn, add a `ModelComponent` to the actor entity: ships/enemies get `{modelHandle, rotationOffset = angleAxis(kShipYaw, +Y)}`; bullets get `{bulletModel, materialOverride = tintMat}` (identity offset). The gameplay `TransformComponent.rotation` stays the pure `angleAxis(yaw, +Y)` heading (the player reads it back for `fwd`); the `kShipYaw` flip lives **only** in `ModelComponent.rotationOffset`, exactly as the proxy carried it as a separate `extraYaw`. `Scene::render` draws every submesh at `t.rotation * rotationOffset`. Gameplay tests stay green; screenshot matches the v0.40 shooter (pixel-diff within the v0.40 tolerance).

## 4. Data flow

```
onLoad:   ModelHandle h = registry.registerModel(loadModel(path, registry, shader));
          obj.add<TransformComponent>(...); obj.add<ModelComponent>({h, normalized, override});
onUpdate: gameplay systems write TransformComponent; m_scene.update(dt) (camera)
onRender: setLightDirection/setPointLights; m_scene.render(renderer, aspect)
            → mesh loop (<Transform,Mesh>)  +  model loop (<Transform,Model>, fit-to-unit, per-submesh)
          ... HUD / text ...
```

## 5. Testing

- **`registerModel`/`model` round-trip** (unit, GL-free): register two `Model`s, assert distinct handles and that `model(h)` returns the stored submeshes/bounds. Lives in the existing renderer/registry test TU (already in `bot_arena_tests`) or a small new one — must NOT pull in GL.
- **`fitToUnitTransform`** (unit, GL-free): for a known `AABB`, assert the matrix maps `bounds` center → origin and the largest extent → unit length. (If already covered, extend rather than duplicate.)
- **`ModelComponent`** is trivial data — no test.
- **`Scene::render` model path** is GL-bound → **screenshot-verified**: models_game matches its baseline; shooter matches the v0.40 baseline (same layout, ship orientation, bullet tint, HUD).
- Full build + `bot_arena_tests` green; shooter gameplay tests unchanged and green.

## 6. Risks & mitigations

- **Include cycle** (`ResourceRegistry` ↔ `ModelLoader`). Mitigation: the data-only `Model.hpp` extraction; `ResourceRegistry` includes only it, not `ModelLoader.hpp`.
- **`materialOverride == 0` sentinel** collides with the valid handle 0. Mitigation: only meaningful for a *model* (overriding to a game's ground material is nonsensical); documented in the header. If a real need arises, a later slice adds an explicit `bool` flag.
- **Shooter behavior drift** (proxy math → single-entity transform). Mitigation: `translate·mat4_cast(rotation·rotationOffset)·scale·fitToUnit` is algebraically identical to the proxy's collapsed `translate(pos + rot·(−uni·center))·R·scale(uni)` (verified by hand); the gameplay rotation stays pure heading so aiming is unchanged; strict before/after screenshot gate + gameplay tests.
- **models_game model-cycling** must reassign `ModelComponent.model`, not recreate the entity. Mitigation: mutate the component in place; verify each cycled model renders.
- **Registry `model()` bounds** on a bad handle. Mitigation: handles come from `registerModel`; treat out-of-range as a programming error (consistent with `registerMesh`/`registerMaterial`).

## 7. Open items (deferred, not blocking)

- `LightComponent` + scene-driven lighting.
- Per-submesh material overrides (a mesh→material map) vs the single `materialOverride`.
- Sort / frustum culling / instanced submission in `Scene::render`.
- `SceneObject::addComponent<T>` empty-tag fix (its own TDD slice).
- Migrating remaining games (particles, camera_demo, billboard_demo) onto `Scene`.

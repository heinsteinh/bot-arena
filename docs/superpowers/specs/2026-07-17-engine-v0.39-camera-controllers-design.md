# Engine v0.39 — Camera Controller Components + Systems (ECS) — Design Spec

**Date:** 2026-07-17
**Status:** Approved for planning
**Scope:** Add the four camera *behaviours* (Fly, Orbit, Follow, 2D) to the v0.38 scene model as **data-oriented controller components + systems** that read `Input`, run in `Scene::update(dt)`, and write the camera's `TransformComponent` (the single pose source). As part of this, migrate `TransformComponent.rotation` from an euler `vec3` to a `glm::quat` (the v0.38 "euler vs quat" open item), which makes look-at orientation robust and gtc-only. A `controller_demo` exercises all four.
**Builds on:** the scene foundation on `main` (v0.38: `Scene`/`SceneObject`/`TransformComponent`/`CameraComponent`, `Scene::cameraUniforms`, `MatrixCamera`).

## 1. Goal & Motivation

v0.38 established that the camera's pose lives in its `TransformComponent`. This slice supplies the *behaviours* that move it — as ECS controller **components** (per-behaviour data) driven by **systems**, not as camera subclasses. The four behaviours are the ones the engine already exposes through the standalone `FlyCameraController`/`OrbitCameraController` plus the reserved Follow and 2D. Because controllers must write orientation from a look-direction, `TransformComponent.rotation` becomes a `glm::quat` — cleaner for arbitrary orientations (Follow), robust for look-at via `glm::quat_cast`, and free of the experimental-header trap euler-from-direction would need.

## 2. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Rotation storage | `TransformComponent.rotation` becomes `glm::quat` (identity default `{1,0,0,0}`); `localTransform`/`viewMatrix` use `glm::mat4_cast(rotation)` directly |
| Controllers | **All four**: `FlyControllerComponent`, `OrbitControllerComponent`, `FollowControllerComponent`, `Camera2DControllerComponent` — distinct components (data differs) |
| Systems | Free functions per controller (`updateFlyControllers(registry, dt)` …) that read `Input::` statically and write `TransformComponent` |
| Invocation | `Scene::update(float dt)` runs the four systems (matches the v0.38 Scene sketch); games call `scene.update(dt)` in `onUpdate` |
| Orientation math | gtc-only: `angleAxis` for yaw/pitch, `quat_cast(mat3(r,u,-f))` for look-at; camera looks down −Z |
| Testability | Pure math (orientation/forward/lookRotation, orbit/follow/2D transform-from-params) unit-tested; `Input`-driven wrappers demo/live-verified |
| Demo | `controller_demo`: one scene, camera's controller component swapped among the four; `BOTARENA_CTRL=0..3` freezes a pose per controller for headless shots |
| Untouched | Old `FlyCameraController`/`OrbitCameraController`/`CameraController` classes + games using them stay; migrating games is a later slice |
| Reserved | Follow damping curves, momentum/inertia, collision, gamepad, per-controller FOV; retiring the standalone controllers |

## 3. Components & changes

### 3.1 `TransformComponent` → quaternion (`Components.hpp`, `SceneCamera.hpp`)
```cpp
struct TransformComponent {
  glm::vec3 translation{0.0f};
  glm::quat rotation{1.0f, 0.0f, 0.0f, 0.0f};   // was glm::vec3 euler
  glm::vec3 scale{1.0f};
  glm::mat4 localTransform() const {            // translate * mat4_cast(rotation) * scale
    return glm::translate(glm::mat4(1.0f), translation) *
           glm::mat4_cast(rotation) * glm::scale(glm::mat4(1.0f), scale);
  }
};
```
`viewMatrix` (`SceneCamera.hpp`) becomes `inverse(translate(t.translation) * mat4_cast(t.rotation))`.

**Migration (v0.38 scene code only — nothing else uses this field):**
- `games/scene_demo/SceneDemoGame.cpp` — replace `ct.rotation = {radians(-24),0,0}` with `glm::quat(glm::vec3(glm::radians(-24.0f), 0.0f, 0.0f))` (or `orientationFromYawPitch`).
- `tests/test_scene.cpp` — the `localTransform`/`viewMatrix`/`cameraUniforms` cases that set `rotation` to an euler `vec3` now set a `glm::quat` (build the expected matrix from the same quat). This also **strengthens** the v0.38 tests flagged as partially tautological: the localTransform test can now assert a hand-checked basis vector from a 90° rotation.

### 3.2 Camera math (`engine/scene/CameraMath.hpp`, header-only, pure, tested)
```cpp
inline glm::quat orientationFromYawPitch(float yawDeg, float pitchDeg);   // angleAxis(yaw,Y)*angleAxis(pitch,X)
inline glm::vec3 forwardDir(const glm::quat& q);                          // q * (0,0,-1)
inline glm::quat lookRotation(const glm::vec3& forward,
                              const glm::vec3& up = {0,1,0});             // quat_cast(mat3(r,u,-f))
inline glm::vec3 orbitPosition(const glm::vec3& center, float yawDeg,
                               float pitchDeg, float distance);          // center - forwardDir(orient)*distance
```
Convention (pinned by tests): `yaw=pitch=0` → looks down −Z; +yaw turns about world +Y; +pitch pitches about local +X. `lookRotation(dir)` orients −Z along `dir`.

### 3.3 Controller components (`engine/scene/ControllerComponents.hpp`, data only)
```cpp
struct FlyControllerComponent {
  float moveSpeed = 6.0f, lookSensitivity = 0.08f, yaw = -135.0f, pitch = -30.0f;
};
struct OrbitControllerComponent {
  entt::entity target = entt::null;   // if valid, orbit its TransformComponent.translation; else targetPoint
  glm::vec3 targetPoint{0.0f, 0.5f, 0.0f};
  float yaw = 45.0f, pitch = 30.0f, distance = 14.0f;
  float minDistance = 3.0f, maxDistance = 40.0f, rotateSpeed = 0.25f, zoomSpeed = 1.5f;
};
struct FollowControllerComponent {
  entt::entity target = entt::null;   // required; camera sits at target + offset, looking at target
  glm::vec3 offset{0.0f, 4.0f, 9.0f};
  float damping = 0.0f;               // 0 = hard follow; >0 = exponential smoothing toward the goal
};
struct Camera2DControllerComponent { // top-down/2D ortho: pan translation.xy, zoom orthoSize, identity rotation
  float panSpeed = 8.0f, zoomSpeed = 1.5f;
};
```

### 3.4 Systems (`engine/scene/CameraControllerSystems.hpp/.cpp`)
Free functions, one per controller, iterating `registry.view<TransformComponent, XControllerComponent>()`, reading `Input::` + `dt`, and writing the transform via §3.2:
- **Fly:** right-drag updates `yaw/pitch` (clamped ±89 pitch); WASD/QE moves `translation` along the yaw-planar forward/right; `rotation = orientationFromYawPitch(yaw, pitch)`.
- **Orbit:** left-drag updates `yaw/pitch`; scroll updates `distance` (clamped); center = `target`'s translation if valid else `targetPoint`; `translation = orbitPosition(center, yaw, pitch, distance)`, `rotation = orientationFromYawPitch(yaw, pitch)`.
- **Follow:** goal = `target`'s translation + `offset`; `translation` = goal (or damped lerp toward it); `rotation = lookRotation(targetTranslation - translation)`. No-op if `target` invalid.
- **Camera2D:** WASD/arrows pan `translation.xy` by `panSpeed*dt`; scroll adjusts the camera's `CameraComponent.orthoSize` (zoom); `rotation` = identity (looks down −Z).

`Scene::update(float dt)` (new, `Scene.hpp/.cpp`) calls all four in order.

### 3.5 Demo `controller_demo`
`controllerdemo::ControllerDemoGame` (`controller_demo_game`): one `Scene` with a ground + object arrangement and a **camera entity** that carries one controller component at a time. A key (e.g. `Tab`/number keys) cycles which controller component is attached (like the v0.31 `camera_demo` toured four views). `onUpdate` calls `scene.update(dt)`; `onRender` sets the renderer camera from `scene.cameraUniforms(aspect)`. `BOTARENA_CTRL=0..3` selects the controller and a scripted pose for a deterministic headless screenshot per behaviour; live interactivity (drag/WASD/scroll) is user-verified.

## 4. Data flow

```
Application loop: Input::beginFrame() -> layer.onUpdate(dt)
game.onUpdate(dt): scene.update(dt)
  Scene::update runs the 4 systems:
    each: view<TransformComponent, XController> x Input:: + dt
          -> CameraMath -> write TransformComponent (translation + quat rotation)
game.onRender: renderer.setCamera(scene.cameraUniforms(aspect))   // view = inverse(T*R) from the transform
             ... submit meshes via MeshRenderer + MatrixCamera (v0.38 path) ...
```

## 5. Testing

- **Pure math (`tests/test_scene.cpp`, CPU):** `orientationFromYawPitch(0,0)` forward == `(0,0,-1)`; +yaw/+pitch turn the expected way; `lookRotation(dir)` yields `forwardDir == normalize(dir)` and `viewMatrix(translate=eye, rotation=lookRotation(target-eye))` ≈ `glm::lookAt(eye, target, up)`; `orbitPosition(center, yaw, pitch, d)` sits distance `d` from center along `-forward`; a follow goal = `target + offset` with `lookRotation` facing the target; a 2D pan shifts `translation.xy`.
- **Strengthened v0.38 tests:** with quat rotation, the `localTransform` test asserts a hand-checked basis vector from a 90°-about-Y rotation (independent oracle, resolving the earlier tautology note).
- **`Input`-driven systems:** verified via `controller_demo` (live drag/keys) + a per-controller deterministic screenshot at a scripted pose (`BOTARENA_CTRL`), consistent with the renderer's screenshot-verified convention.
- **Regression:** existing games (old controllers) untouched; full build + suite green.

## 6. Risks & mitigations

- **Quat refactor breaks v0.38 consumers.** Only `scene_demo` + `test_scene.cpp` reference `TransformComponent.rotation`; both migrate in the same task. Mitigation: a focused unit test that `viewMatrix` of a quat transform equals `glm::lookAt` for a lookRotation.
- **Orientation convention ambiguity (yaw/pitch sign, gimbal).** Mitigation: convention pinned by unit tests (`orientationFromYawPitch(0,0)` and sign-of-turn cases) and confirmed by the demo screenshot; gtc `angleAxis`/`quat_cast` only, no gtx.
- **`Input` is a global → systems not directly unit-testable.** Mitigation: the pose math is factored into pure functions that ARE tested; the `Input` glue is thin and demo/live-verified.
- **`Scene::update` couples the scene module to `Input`.** Accepted: `Input` is an engine-core global the existing controllers already use; `Scene::update` is opt-in (games that don't call it pay nothing).
- **Dangling `target` entity** in Orbit/Follow. Mitigation: systems validate `registry.valid(target)` and fall back (orbit → `targetPoint`; follow → no-op).

## 7. Open items (deferred, not blocking)

- Follow damping curves / spring, camera momentum & inertia, collision-aware orbit.
- Gamepad input; per-controller FOV / projection presets.
- Retiring the standalone `FlyCameraController`/`OrbitCameraController`/`CameraController` and migrating `arena`/`shooter`/`camera_demo` onto scene controllers.
- A `Scene::update` system-registration mechanism (custom user systems) instead of a fixed built-in list.

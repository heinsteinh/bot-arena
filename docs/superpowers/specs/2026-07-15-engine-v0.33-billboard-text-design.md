# Engine v0.33 — World Billboard Text (Damage Numbers) — Design Spec

**Date:** 2026-07-15
**Status:** Approved for planning
**Scope:** Camera-facing **billboard** 3D text — a text run anchored at a world point, always facing the camera, sized in world units (perspective-scaled), drawn **always-on-top** of the scene. SDF-capable fonts only; rich-text spans supported. Reuses the SDF effect fragment shader (new vertex stage only). A new `billboard_demo` game shows floating damage numbers over enemies.
**Builds on:** v0.28–v0.32 text system + the SDF effect shader (all on `main`; includes the #33 orbit-camera fix the demo relies on).
**Design source:** ADR-2 world-placement modes (world-text slice).

## 1. Goal & Motivation

Text is currently screen-space overlay only. This slice adds `CameraBillboard` placement: a string
anchored at a `worldPos`, transformed local → world → clip on the GPU via the camera, facing the
camera and shrinking with distance. Use case: damage numbers floating over enemies. Always-on-top,
so no deferred-pipeline surgery (the same post-composite overlay phase draws it).

The SDF **fragment** shader (effects) is identical for screen and world text; only the **vertex**
stage differs. The camera-basis extraction is already proven in the engine's particle/emissive
billboard shaders.

## 2. Decisions (locked)

| Area | Decision |
| --- | --- |
| Mode | `CameraBillboard` only. Reserved: `WorldOriented`, `AxisBillboard`, depth-occlusion, constant-apparent-size, HDR/bloom participation |
| Sizing | True world-space: `worldOffset = localPixelOffset * worldUnitsPerPixel` — physical size, shrinks with distance. NOT constant-screen-size |
| Draw | Always-on-top overlay; depth test + write OFF; SDF-only |
| Fonts | SDF-capable only (`font.supportsDistanceFieldEffects()`, true for SDF/MSDF); non-DF font → structured warning + no batch (documented no-op) |
| Rich text | Supported (spans), continuous layout across span boundaries |
| API | Named factories on `TextPlacement` (no fragile aggregate init) |

### Billboard basis (verified, not speculative)
The world vertex shader derives the camera's world-space right/up from the camera UBO's `view`:
```glsl
mat3 camRot = transpose(mat3(uView));   // camera->world rotation; cols = right, up, back
vec3 right = camRot[0];
vec3 up    = camRot[1];
```
This equals `vec3(uView[0][0], uView[1][0], uView[2][0])` etc. — the exact form the engine's
particle/emissive billboard vertex shaders already use and render correctly at any camera
orientation. **Invariant:** changing camera yaw or pitch changes billboard orientation but never
mirrors, rolls, or skews the text. Validated at render time with a rotated + elevated orbit camera
(§7, test 17).

## 3. Placement API (structured — no aggregate init)

`TextPlacement` gains `glm::vec3 worldPos{0.0f}` and **named factories**; the existing public fields
stay (so current screen callers keep working), but new code uses factories:
```cpp
struct TextPlacement {
  PlacementMode mode = PlacementMode::ScreenSpace;
  glm::vec2 pos{0.0f};        // screen: baseline pixel origin
  float scale = 1.0f;         // screen: px multiplier | billboard: worldUnitsPerPixel (>0)
  glm::vec3 worldPos{0.0f};   // billboard: anchor

  static TextPlacement screen(glm::vec2 pos, float scale = 1.0f);
  // worldUnitsPerPixel is clamped to a small positive minimum (never <= 0), so a
  // non-positive value can never mirror text. Documented in §6.
  static TextPlacement cameraBillboard(glm::vec3 worldPos, float worldUnitsPerPixel);
};
```
`worldUnitsPerPixel` is documented in-code as world units per local (atlas) pixel; the factory is the
single place billboard defaults/validation live.

## 4. Anchor & alignment semantics (deterministic)

For `CameraBillboard`, v0.33 fixes:
- **Horizontal alignment:** center, on the run's **logical width** (total pen advance) — consistent
  anchoring for equal-advance strings like `"111"` vs `"888"`. (Logical, not visual, bounds; visual
  bounds — bearings/overhang/outline — are a reserved refinement.)
- **Vertical anchor:** **baseline** at `worldPos` (text rises above the anchor).
- **Local → world axes:** local layout is y-down (baseline at 0); convert to world with `+x` right,
  `+y` up: `offset = { (localX - logicalWidth/2), -localY } * worldUnitsPerPixel`.
- **Multiline:** not supported this slice (single line; `\n` is a missing glyph as today).

Centering uses the layout result's logical width (final `TextLayoutState.penX` after laying out the
whole run), **not** re-derived per span and **not** from a single glyph. A fuller
`TextLayoutResult { quads, pen, logicalBounds, visualBounds }` shared by screen + billboard paths is
a reserved refinement; v0.33 uses logical width and documents the semantics.

## 5. Rich-text / span continuity

The billboard path consumes the same append seam as screen rich text. A multi-span billboard has
**identical geometry** to the equivalent single-style string. Flow:
1. Lay out the **entire ordered span sequence** with one continuous `TextLayoutState` (pen + reserved
   kerning), accumulating quads and, per quad, the owning span.
2. Compute the block's logical width **once** from the final pen; derive the single centering offset.
3. Emit each glyph with its span's deduped `styleIndex` into the world batch.

No per-span re-layout, no per-span centering.

## 6. World-scale semantics

`worldOffset = localPixelOffset * worldUnitsPerPixel`. The label has a physical world size and appears
smaller with distance (perspective). Non-positive `worldUnitsPerPixel` is **clamped to a small
positive minimum by the factory** (never mirrors); the render path also treats a non-positive scale
defensively. Documented as world-space (not constant-screen-size) text.

## 7. Components & changes

### 7.1 `WorldTextVertex` (new header) — SDF-only, no per-vertex colors
```cpp
struct WorldTextVertex {
  glm::vec3 anchor;      // world anchor (same for every glyph of a run)
  glm::vec2 offset;      // world-unit offset along camera right/up
  glm::vec2 uv;          // atlas UV
  uint32_t styleIndex;   // index into the per-batch style table
};                       // 32 bytes
```
The SDF effect fragment reads fill/outline/glow/shadow from the style table by `styleIndex`, so no
per-vertex colors are needed.

### 7.2 `FontAsset::supportsDistanceFieldEffects()`
```cpp
bool supportsDistanceFieldEffects() const {
  return backend == FontBackend::SDF || backend == FontBackend::MSDF;
}
```
Capability check (not a concrete-class check) so MSDF works on this path later.

### 7.3 World vertex shader + reused SDF fragment (§2 basis)
```glsl
#version 460 core
layout(location = 0) in vec3 aAnchor;
layout(location = 1) in vec2 aOffset;
layout(location = 2) in vec2 aUV;
layout(location = 3) in uint aStyle;
layout(std140, binding = 0) uniform Camera {
  mat4 uView; mat4 uProjection; mat4 uViewProjection;
  vec4 uCameraPosition; mat4 uInvViewProjection;
};
out vec2 vUV;
flat out uint vStyleIndex;
void main() {
  mat3 camRot = transpose(mat3(uView));
  vec3 world = aAnchor + camRot[0] * aOffset.x + camRot[1] * aOffset.y;
  vUV = aUV;
  vStyleIndex = aStyle;
  gl_Position = uViewProjection * vec4(world, 1.0);
}
```
Paired with the **existing** SDF effect fragment shader unchanged. §8 confirms the varying interface
matches exactly (`vUV`, `flat vStyleIndex`); `uPxRange`/StyleTable(binding 3)/`uAtlas` are set the
same way as screen SDF text.

### 7.4 `TextRenderer` — a parallel world batch list
- `struct WorldBatch { uint32_t atlas; FontBackend backend; float pxRange; std::vector<GpuStyle> styles; std::vector<WorldTextVertex> verts; }` and `const std::vector<WorldBatch>& worldBatches() const`.
- The style dedup + 64-cap-split logic is **factored to be shared** between screen `Batch` and
  `WorldBatch` (a templated `acquireIn(batches, index, backend, atlas, pxRange, gpuStyle)`), so the
  canonical batch-key structure is identical.
- `submit(...)` routes by `placement.mode`: `ScreenSpace` → the existing screen path; `CameraBillboard`
  → the world path (§4/§5). Empty text → no batch. Non-DF font in billboard mode → `spdlog::warn`
  (once per font/placement combination) + no batch.
- **Batch key:** `atlas` (which, for a given font, uniquely determines `pxRange` and backend — each
  bake mints a unique atlas; a `WorldBatch` still records `pxRange`/`backend` for the draw). Reuses
  the screen SDF key structure. Two fonts sharing an atlas but different `pxRange` cannot occur today;
  the recorded `pxRange` keeps the draw correct regardless.
- **Overflow:** >64 distinct styles split into another `WorldBatch` (same atlas + billboard mode),
  continuing emission of later glyphs, never splitting a glyph, preserving submission order and each
  glyph's anchor/offset.

### 7.5 Backend `drawWorldTextBatch` — explicit render-state ownership
```cpp
virtual void drawWorldTextBatch(uint32_t atlasTextureId,
                                const std::vector<WorldTextVertex>& verts,
                                float pxRange,
                                const std::vector<GpuStyle>& styles) = 0;
```
`OpenGLBackend` owns a world VAO (attribs 0..3 per §7.1), the world program (§7.3 VS + SDF FS), and
reuses the style UBO (binding 3). Per draw, the state is set and restored so nothing leaks into later
passes:
- depth **test** disabled, depth **write** disabled (`glDepthMask(GL_FALSE)` then restored),
- blending enabled, `GL_SRC_ALPHA`/`GL_ONE_MINUS_SRC_ALPHA` (same straight-alpha convention as screen
  text — the SDF FS outputs straight-alpha),
- face culling disabled (billboard quad winding is orientation-dependent) and restored,
- default framebuffer bound (overlay phase),
- camera UBO (binding 0, already uploaded/bound for the frame) + style UBO (binding 3) set,
- atlas bound to unit 0, `uAtlas`/`uPxRange` set,
- state restored (depth test on, depth write on, blend off, cull to prior) after the draw.

### 7.6 `Renderer` — deterministic overlay ordering
`endFrame` draws overlays in a fixed order so HUD stays above billboards:
1. scene composite (existing),
2. **world billboard batches** (`drawWorldTextBatch` per `m_textRenderer.worldBatches()`),
3. **screen-space text batches** (`drawTextBatch` per `m_textRenderer.batches()`).

`m_textRenderer.clear()` clears both lists. API is unchanged: callers use the existing `drawText`
overloads with a `CameraBillboard` placement.

## 8. Fragment-shader coordinate assumptions (verified)

The world VS supplies exactly what the SDF effect FS consumes: `out vec2 vUV` (interpolated) and
`flat out uint vStyleIndex` matching `in vec2 vUV; flat in uint vStyleIndex;` — no `vFill` (the FS
reads colors from the style table). `uAtlas`/`uPxRange`/StyleTable(binding 3) are identical to screen
SDF. `fwidth`-based AA and `screenPxRange` operate in screen space post-projection, so they adapt to
the billboard's on-screen size. **Glow and shadow are screen-derivative-driven** (screen-px offsets),
not physically world-scaled — acceptable and documented for v0.33.

## 9. Demo game `billboard_demo` (deterministic)

`billboarddemo::BillboardDemoGame` (`billboard_demo_game` target), like the other games:
- An orbiting camera with **non-zero yaw and pitch**; a small scene of enemy cubes.
- A damage-number system: `struct DamageNumber { glm::vec3 worldPos; std::string text; glm::vec4 color; float age; };` — the formatted **`text` is owned by the struct** (not a transient), spawned over enemies, rising (`worldPos.y += dt*speed`), fading (alpha by `1 - age/lifetime`), expiring (~1.2 s).
- Rendered as `renderer.drawText(m_sdf, dmg.text, TextPlacement::cameraBillboard(dmg.worldPos, worldUnitsPerPixel), style)` with an **outline** for readability and color by magnitude (white → orange → yellow crit).
- **Deterministic under screenshot:** fixed RNG seed; enemy motion frozen (or `m_time`-derived) when `BOTARENA_SCREENSHOT` is set; damage numbers **pre-seeded** in `onAttach` so a single frame shows ≥3 labels at different distances, one high-value crit style, and one partially-faded label, not fully overlapping. A `BOTARENA_ORBIT` env (or preset) selects the camera yaw/pitch so the rotated-camera validation (test 17) can capture ≥2 angles.
- The demo also draws a screen-space HUD title to prove ordering (HUD over billboards, test 18).

Visual proof: camera-facing behavior, perspective scaling, alpha fading, outline readability,
always-on-top, and rotation-invariance.

## 10. Lifetime contract

Text submission is **synchronous**: `submit` lays out and emits vertices within the `drawText` call;
neither `TextSpan::text` nor the string argument is retained. A temporary `std::string` passed to
`drawText` is therefore safe. The demo nonetheless stores `DamageNumber::text` (formatted once at
spawn) — clearer and avoids per-frame formatting. Documented in-code.

## 11. Testing

CPU unit tests (no GL) in `tests/test_text_batch.cpp` using a stub SDF `FontAsset` and a stub
non-SDF font:
1. `CameraBillboard` routes only to world batches.
2. `ScreenSpace` routes only to screen batches.
3. Every vertex of one billboard shares the same `anchor`.
4. Offsets derive from the complete text block (not per span).
5. One-span and multi-span billboards have identical positions.
6. Horizontal centering uses the logical width (documented bounds).
7. Y-down layout converts to world `+y` up (a glyph above the baseline has `offset.y > 0`).
8. Positive `worldUnitsPerPixel` yields the expected world offsets.
9. Zero/negative `worldUnitsPerPixel` → clamped positive (no mirror): offsets keep sign, never negated.
10. Empty text produces no batch.
11. Empty spans allocate no style.
12. Equal styles deduplicate.
13. >64 styles split world batches without changing glyph order.
14. Different `pxRange` (⇒ different atlas id) do not merge into one batch.
15. Non-DF font in billboard mode → documented diagnostic + no batch.
16. Temporary-string submission is safe (submit from a temporary; verts produced correctly).

Render/integration (screenshot-inspected by the controller):
17. A rotated + elevated camera confirms the text stays upright and faces the camera (≥2 angles).
18. World billboards render below screen-space HUD text (overlay ordering).

Existing `[text]`/`[textbatch]` tests stay green.

## 12. Risks & mitigations

- **Wrong billboard basis / mirror/skew.** Mitigated: `transpose(mat3(uView))` matches the proven
  particle-shader convention; invariant + rotated-camera validation (test 17).
- **FS varying mismatch → link error / garbage.** Mitigated: §8 verified the FS consumes exactly
  `vUV` + `flat vStyleIndex`; the world VS outputs exactly those.
- **State leak from the overlay draw.** Mitigated: §7.5 sets and restores depth test/write, blend,
  cull.
- **Centering drift for spans / equal-width strings.** Mitigated: single logical-width centering over
  the whole run; tests 4/5/6.
- **Non-positive scale mirroring.** Mitigated: factory clamps to positive; test 9.
- **Transient string lifetime.** Mitigated: synchronous submission (§10); demo owns the string.
- **Batch merge of incompatible fonts.** Mitigated: atlas key ⇒ pxRange/backend; `WorldBatch` records
  `pxRange`; test 14.

## 13. Open items (deferred, not blocking)

- `WorldOriented` (arbitrary transform) and `AxisBillboard`.
- Depth-occluded world text (draw inside the scene pass with the depth buffer bound).
- Constant-apparent-size option; world-scaled glow/shadow.
- Shared `TextLayoutResult` metrics (logical + visual bounds) for both paths; multiline blocks.
- HDR/bloom participation for world text.

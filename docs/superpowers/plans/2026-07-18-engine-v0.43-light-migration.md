**Goal:** Migrate the three remaining Scene-based games (shooter, models, controller_demo) onto `LightComponent`, and guard `collectLights` against the zero-vector directional NaN.

**Architecture:** Same mechanical migration as v0.42's scene_demo/arena: create the light `SceneObject` in `onAttach`, delete the manual `renderer.setLightDirection`/`setPointLights` calls from `onRender`. `collectLights` gains a squared-length guard (core GLM `glm::dot`, no `gtx`) so a degenerate zero-translation directional is ignored rather than producing NaN. `Scene::render` wiring stays additive.

**Tech Stack:** C++17, OpenGL 4.6 deferred renderer, EnTT, GLM, Catch2 (`bot_arena_tests`), CMake.

- [ ] **Step 1: Write the failing tests**

Append two cases to `tests/test_light_collection.cpp` (match the existing file's Catch2 style and its `makeLight` helper — which creates an entity with a `TransformComponent` at a given position plus a `LightComponent`):

```cpp
TEST_CASE("collectLights: zero-translation directional is ignored") {
  entt::registry reg;
  LightComponent d;
  d.type = LightType::Directional;
  makeLight(reg, glm::vec3(0.0f, 0.0f, 0.0f), d);

  const CollectedLights cl = engine::collectLights(reg);
  CHECK_FALSE(cl.hasDirectional);
  CHECK(cl.points.empty());
}

TEST_CASE("collectLights: zero directional does not consume the first slot") {
  entt::registry reg;
  LightComponent zero;
  zero.type = LightType::Directional;
  makeLight(reg, glm::vec3(0.0f, 0.0f, 0.0f), zero);
  LightComponent valid;
  valid.type = LightType::Directional;
  makeLight(reg, glm::vec3(0.5f, 0.7f, 0.35f), valid);

  const CollectedLights cl = engine::collectLights(reg);
  REQUIRE(cl.hasDirectional);
  const glm::vec3 expect = glm::normalize(glm::vec3(0.5f, 0.7f, 0.35f));
  CHECK(cl.directionalDir.x == Catch::Approx(expect.x));
  CHECK(cl.directionalDir.y == Catch::Approx(expect.y));
  CHECK(cl.directionalDir.z == Catch::Approx(expect.z));
}
```

Note: the second test relies on both directional entities being visited by the view — the guard must skip the zero one without setting `hasDirectional`, so the valid one (whichever order the view visits them) becomes the winner. If the zero entity is visited first, the guard skips it; if the valid entity is visited first, it wins and the zero one is ignored by the existing `!hasDirectional` gate. Either way the result is the valid direction.

- [ ] **Step 2: Run the new tests to confirm they fail**

Run: `cmake --build build --target bot_arena_tests 2>&1 | tail -5 && ./build/bot_arena_tests "collectLights: zero*" 2>&1 | tail -8`
Expected: the first new case FAILS — the unguarded `glm::normalize({0,0,0})` sets `hasDirectional=true` with a NaN direction, so `CHECK_FALSE(cl.hasDirectional)` fails. (The build itself succeeds; this is a behavioral RED, not a compile RED.)

- [ ] **Step 3: Add the guard**

In `engine/scene/LightCollection.hpp`, replace the directional branch:

```cpp
    } else if (!out.hasDirectional) {
      out.hasDirectional = true;
      out.directionalDir = glm::normalize(t.translation);
    }
```

with a squared-length-guarded version:

```cpp
    } else if (!out.hasDirectional &&
               glm::dot(t.translation, t.translation) > kMinDirLen2) {
      out.hasDirectional = true;
      out.directionalDir = glm::normalize(t.translation);
    }
```

and add the constant just inside `collectLights`, before the `for` loop:

```cpp
  // A directional light's direction is normalize(translation); a ~zero
  // translation would yield NaN, so such a degenerate directional is ignored
  // (it does not consume the first-directional slot). glm::dot(v,v) is squared
  // length using core GLM only -- glm::length2 lives in gtx, which is banned.
  constexpr float kMinDirLen2 = 1e-12f;
```

Update the function's doc comment (lines ~23-27) to note that a zero-translation directional is ignored.

Run: `cmake --build build --target bot_arena_tests 2>&1 | tail -3 && ./build/bot_arena_tests "collectLights: zero*" 2>&1 | tail -6`
Expected: both new cases PASS.
